# Аш-Шифахия — интерактивный курс арабского языка

> Короткая памятка для агентов, читающих , — в [AGENTS.md](./AGENTS.md);
> она отсылает сюда. Этот файл — источник истины.

Учебное веб-приложение на русском языке по книге «Аш-Шифахия». Пользователь
проходит уроки: карточки со словами → тест с вариантами ответа → результат,
плюс отдельный режим ежедневного повторения по системе Лейтнера.

Интерфейс, контент и коммуникация с пользователем — на русском. Код,
идентификаторы, коммиты и комментарии в коде — на английском.

## Стек и платформа

- **Next.js 16 App Router** поверх [**vinext**](https://github.com/cloudflare/vinext) —
  рантайм App Router для Cloudflare Workers. Сборка/дев идут через `vinext`,
  а не через `next`. `wrangler.jsonc` не используется: локальные биндинги
  описаны прямо в `vite.config.ts`.
- **React 19**, **Vite 8**, **Tailwind 4** (подключён, но вёрстка почти целиком
  на своём CSS в `app/globals.css`).
- Хостинг — платформа OpenAI Sites. `.openai/hosting.json` объявляет
  опциональные биндинги D1/R2 (сейчас оба `null`); ни один не используется.
  Публикуется же собранная статика на GitHub Pages (см. «Публикация»).
- **Supabase** — единственная внешняя зависимость приложения, и та
  необязательная: только вход и синхронизация прогресса между устройствами.
- Node.js `>= 22.13.0`.

## Публикация

Приложение целиком рендерится в браузере и держит состояние в `localStorage`,
поэтому курс работает и как набор статических файлов.
`scripts/build-static.mjs` рендерит **все три страницы** (`/`, `/podcasts` и
`/topics`) через собранный Worker, переписывает абсолютные адреса ассетов на относительные (иначе сайт ломается в подкаталоге —
для этого же в `vite.config.ts` есть `base: process.env.STATIC_BASE ?? "/"`) и
складывает всё в `.static-site/`. Рерайт нужен в двух местах: в разметке и в
экранированном payload гидрации — React пересобирает `<head>` на клиенте.

**Глубина страницы важна.** `/` лежит в корне и тянет ассеты через `./`,
`/podcasts` и `/topics` лежат на уровень ниже и тянут их через `../`. Переписывать надо не
только абсолютные адреса: при `STATIC_BASE=./` Vite уже выдаёт ассеты
относительными (`./assets/…`), и на вложенной странице они разрешились бы в
`/podcasts/assets/…` — то есть в 404.

**Переписывается по тому, что говорит адрес, а не по синтаксису вокруг него.**
Правило, знавшее только про `src=` и `href=`, один адрес пропускало: входной
чанк загружается встроенным `import("./assets/…")`, где нет ни того, ни
другого. Страница при этом рендерилась и молча оставалась мёртвой — React не
гидрировался, ни одна кнопка не работала. Ретроспективный взгляд lookbehind'а в
регулярке нужен затем, чтобы уже переписанный `../assets/` не был принят за
свой собственный `./assets/`.

**Проверка — не по разметке, а по файлам.** `verifyAssets` разрешает каждый
упомянутый адрес относительно самой страницы, как это делает браузер, и падает,
если файла там нет. Именно это ловит промах любого правила переписывания, чем
бы адрес ни был записан.

Маршрут запрашивается у Worker **без** конечного слеша (`/podcasts`), иначе Next
отвечает 308, а кладётся всё равно в `podcasts/index.html`.

`.github/workflows/deploy.yml` повторяет сборку на каждый push в `main` и
выкладывает результат в ветку `gh-pages`; GitHub Pages отдаёт её по адресу
`https://shifahiya-project.github.io/ash-shifahiya-app/`. Ветка `gh-pages`
содержит только собранный сайт и переписывается целиком — руками её не править.

## Модель данных

`content/types.ts` — единственный источник истины:

```ts
type Word = { arabic: string; russian: string; note?: string; audio?: string };
type Question = {
  prompt: string; promptLang: "ar" | "ru";
  answer: string; options: string[]; explanation: string;
};
type GrammarRule = {
  kind: "nahw" | "sarf";
  title: string; term?: string; pattern?: string; explanation: string;
  examples: { arabic: string; russian: string; note?: string }[];
};
type GrammarBlock = {
  title: string; intro: string;
  rules: GrammarRule[]; questions: Question[];
};
type Lesson = {
  id: number; arabicTitle: string; title: string; description: string;
  tags: string[];
  decks: { title: string; words: Word[] }[];
  questions: Question[];
  grammar?: GrammarBlock;
};
```

Сейчас: 100 уроков, ~6740 словоформ, ~1075 авторских вопросов.

### Грамматика в этом виде не показывается

`GRAMMAR_ENABLED = false` в `app/features.ts` — один выключатель на всё.
**Это решение автора, а не отложенная задача:** грамматика в том виде, в каком
она здесь написана, курсу не показывается. Не ищите, что доделать, чтобы её
включить, и не включайте сами.

**Ничего не удалено:** блоки лежат в файлах уроков, грамматические вопросы —
в экзаменах, а счёт `shifahiya-grammar-{id}` остаётся в хранилище и продолжает
синхронизироваться. Материал сохранён на случай, если к нему вернутся в другом
виде; технически выключатель обратим — `false` на `true`, больше ничего.

Пока выключатель выключен:

- у урока нет грамматической части, он кончается своими словами;
- урок засчитывается по одному своему счёту — никого не держат на блоке,
  которого не видно;
- экзамены отдают только лексику: 80 вопросов вместо 100 (проходной 61) и
  114 вместо 150 (проходной 86);
- урок, брошенный внутри блока, считается пройденным: карточки и задания у
  ученика позади, и его счёт берётся из сохранённой сессии. Хранилище при этом
  не переписывается — включите грамматику обратно, и незаконченный блок
  вернётся ровно там, где был.

Правила ниже описывают блок таким, каким он был написан, — они сохранены как
описание материала, а не как план его показать. Функции доступа
(`isGrammarPassed`, `isLessonComplete`, `unlockedLessonIds`, `examReadiness`)
принимают выключатель последним аргументом, поэтому обе позиции проверяются
тестами: `tests/lesson-access.test.mjs` — включённую, `tests/features.test.mjs` —
выключенную.

### Грамматический блок (нахв и сарф)

Урок может нести разбор правил, по которым построены его формы. Блок —
**последняя часть урока**: сначала карточки и задания, потом теория и практика
к ней. `lessonParts` добавляет часть с `kind: "grammar"`; у неё нет колод, а
`questionStart/questionEnd` индексируют `grammar.questions`, а не `questions`.
Урок с одной частью получает часть 2, урок с двумя — часть 3.

- **Практика — обычный `Question`.** Движок заданий, счёт и сохранение сессии
  работают без изменений; новый экран нужен только для правила.
- **Блок обязателен, и его нужно сдать.** `isLessonComplete` в
  `app/lesson-access.ts` требует счёт урока и **не меньше 75%** верных ответов
  в блоке (`GRAMMAR_PASS_RATIO`, порог считает `grammarPassMark`). Карточки
  можно просто пролистать, а наполовину понятое правило хуже непонятого:
  следующий урок всё равно на нём строится. Правило «пройденное не отнимаем»
  действует и здесь: блок, добавленный к давно пройденному уроку, не закрывает
  ни его, ни то, что ученик уже открыл, — слабая попытка тоже.
- **Счёт хранится отдельно** — `shifahiya-grammar-{id}`, не подмешивается к
  счёту урока. Иначе у всех, кто прошёл урок до появления блока, результат
  выглядел бы просевшим («26/28» превратилось бы в «26/56»).
- **Лексика — только пройденная.** `tests/grammar-block.test.mjs` проверяет это
  машинно: весь арабский в блоке урока N должен встречаться в колодах уроков
  1..N по согласному скелету (огласовки снимаются, приставочный `و` отделяется).
  Исключение — грамматические термины, они перечислены в тесте поимённо.
- **Термин учат как слово.** У правила рядом с арабским `term` идёт `termSound` —
  как термин звучит, кириллицей: `مُبْتَدَأٌ` → «мубтада», `نَصْبٌ` → «насб».
  Ученик, знающий только «подлежащее», не спросит про مبتدأ и не узнает его на
  слух. В ранних блоках термин вводится вместе с русским переводом, дальше по
  курсу — уже без него: «ставит мубтаду в насб». Транскрипция кириллицей,
  `ع` и `ء` внутри слова передаются через «ъ» (наът, маърифа, мафъуль бихи);
  тест требует `termSound` у каждого правила с `term`.
- **Уроки 97–100 закрывают курс разбором, а не правилами.** Их блоки не вводят
  нового: берут фразу самого урока и учат её разбирать — إِعْرَابٌ «иъраб».
  97 — именное предложение целиком, 98 — сравнение и частицы, переставляющие
  падеж, 99 — глагольное предложение в рассказе, 100 — два прохода: вазн даёт
  значение слова, иъраб — его роль. Поэтому лексика там сходится сама: весь
  арабский взят из колод того же урока.
- Экран правила — `view: "grammar"`, разметка `.rule-card` в `app/globals.css`.

### Тексты для чтения в этом виде не показываются

`READING_ENABLED = false` в `app/features.ts`. В переводах двадцати пяти текстов
нашлось слишком много ошибок, и **автор решил, что в этом виде слой ученику не
показывается.** Это не задача «вычитать и включить»: первая часть состоит из
одной «Шифахии». **Вторая часть не затронута** — её тексты из других книг и к
этому отношения не имеют.

**Ничего не удалено:** `content/reading/section-*.ts`, манифест, экран чтения и
расписание на месте, а записи `shifahiya-reading-v1` остаются в хранилище — у
того, кто читал, история сохраняется. Материал сохранён на случай, если к нему
вернутся в другом виде; технически выключатель обратим.

Убрать это оказалось дёшево ровно потому, что курс на чтение никогда не
опирался: оно не давало карточек, не влияло на счёт и ничего не открывало.
Скрыто оно двумя точками входа — `visibleDueReadings` (карточка «на повторное
чтение» на главной) и `hasVisibleReading` (кнопка на карточке урока); обе
проверяются `tests/features.test.mjs`.

Дальше описан сам слой — как устройство сохранённого материала, не как план.

Отдельный слой поверх курса: связные тексты по методу Франка из книги
«Мабдауль кыраат» — арабское предложение, по нажатию открывается русский
перевод. Это чтение, а не заучивание.

- **Лексика текстов в курс не входит.** Ни карточек, ни дистракторов, ни
  влияния на счёт и на открытие следующего урока. Условие, при котором чтение
  вообще добавляли: оно расширяет, что ученик может прочесть, а не то, что
  курс с него спрашивает.
- **Один текст на урок, уроки 35–96.** Хозяина выбирает не рука, а правило в
  `scripts/import-reading.mjs`: урок из этого промежутка без грамматического
  блока (он уже даёт уроку свою часть), из таких — с наименьшим числом заданий.
  Деление урока надвое хозяину не мешает: чтение — экран рядом с уроком, а не
  третья его часть. Требование «урок из одной части» пришлось снять, когда
  уроки закрыли книгу полностью: после этого делится почти каждый, и текстам
  стало негде жить. Сейчас это 25 уроков: 36, 40, 41, 42, 52, 65,
  66, 67, 69, 73, 75, 77, 78, 81, 82, 83, 84, 86, 87, 88, 90, 91, 92, 95, 96.
- **Своё расписание повторения** — `READING_INTERVALS = [2, 4, 7, 15, 31]` дней
  в `app/reading-review.ts`, ключ `shifahiya-reading-v1`. Коробки Лейтнера тут
  не подходят: текст не забывается за день и не вспоминается наполовину.
  Повторное чтение интервал только удлиняет, на последнем шаге держит.
- **Импорт данных**: `node scripts/import-reading.mjs <файл.json>` разбирает
  выгрузку переводчика в `content/reading/section-NN.ts` и пересобирает
  `content/reading-manifest.ts`. Скрипт понимает обе выгрузки: раннюю (пары с
  полем `lesson`, тексты размечены строками `type: "title"`) и сверенную с
  оригиналом (пары `id`/`section`/`ar`/`ru` без разметки текстов). Деление на
  50 текстов — книжное, поэтому оно хранится в скрипте таблицей `TEXT_STARTS`:
  id первой пары каждого текста. Повторный импорт его не теряет.
- **Название книги живёт в скрипте** (`SOURCE_TITLE`), а не берётся из выгрузки:
  сверенный экспорт называет её «Мабдауль усуль», книга же — «Мабдауль кыраат».
- **Текущая версия — сверенная с печатным оригиналом** (850 пар, 25 разделов).
  По сравнению с первой выгрузкой исправлено 582 перевода и 65 арабских
  фрагментов (71 замена внутри них). Одна особенность оставлена как в книге:
  в разделе 24 напечатано `إِذَا تَسْتَعْمِلِ الدَّوَاءَ ... لَا تُشْفَى أَبَدًا`, и перевод
  сохранён буквально — отрицания, которого нет в оригинале, не добавляли.
- Экран — `view: "reading"`, разметка `.reading-view` в `app/globals.css`.
  Чанк текста грузится при открытии, в стартовую разметку не попадает.

### Экзамены

Две контрольные точки: промежуточная после 50-го урока и итоговая после 100-го.
Карточка экзамена стоит в списке уроков там, где ему место, — сразу за уроком,
после которого он открывается.

- **Размер и состав.** Промежуточный — 100 вопросов, из них ровно 20 по
  грамматике. Итоговый — 150, грамматики не больше четверти (сейчас 36).
  Остальное — лексика: слова, устойчивые выражения и целые фразы; не меньше 70%
  лексических вопросов должны быть длиннее одного слова, это проверяет тест.
- **Проходной балл — три четверти и ещё один ответ**: `examPassMark` в
  `app/lesson-access.ts` даёт 76 из 100 и 114 из 150. Ровно три четверти — это
  черта, а черту нужно перейти.
- **Мелких вопросов нет.** Ни «как будет он», ни отдельного вопроса про
  окончание принадлежности — но и местоимения, и эти окончания встречаются
  внутри конструкций. Список запрещённых «вопросов в одно слово» лежит в
  `tests/exam.test.mjs` и проверяется машинно.
- **Лексика — только пройденная**, как и в грамматических блоках: весь арабский
  промежуточной работы должен встречаться в уроках 1–50, итоговой — в 1–100.
  Проверка сверяет согласный скелет, снимая огласовки, `و` и артикль.
- **Экзамен ничего не закрывает.** Он открывается, когда все уроки до него
  пройдены (включая грамматические блоки), и слабая попытка не отнимает ни
  открытого урока, ни прежнего результата: в `shifahiya-exams-v1` хранится
  лучший балл, число попыток и дата первой сдачи.
- **Работа сохраняется после каждого ответа** (`shifahiya-exam-session`): сто
  ответов слишком много, чтобы потерять их вместе с вкладкой. Порядок вопросов
  тасуется один раз при старте и хранится вместе с сессией.
- **Разбор — только в конце.** По ходу работы ответ не комментируется; на экране
  результата показываются первые 20 ошибок с верным ответом и объяснением.

## Вторая часть курса

Продолжение первой: упор на чтение, лексика идёт к текстам, а не тексты к
лексике. Источники — шесть книг подряд, все загружены: **105 уроков, 3290
новых слов и 3392 фразы в 253 рассказах**.

| Книга | Уроки | Слов | Фраз |
|---|---|---|---|
| Мабдауль кыраат. Часть 2 | 1–14 | 517 | 658 |
| Мабдауль кыраат. Часть 3 | 15–30 | 1051 | 870 |
| Аль-Кыраа ар-рашида. Часть 1 | 31–42 | 219 | 380 |
| Аль-Кыраа ар-рашида. Часть 2 | 43–67 | 818 | 696 |
| Мин адаб аль-ислам | 68–80 | 363 | 277 |
| Та‘лим аль-мута‘аллим | 81–105 | 322 | 511 |

Последние две книги — не рассказы, а разделы: у «Мин адаб аль-ислам» это
пронумерованные правила этикета, у «Та‘лим аль-мута‘аллим» — главы трактата,
поэтому названия уроков там длинные и одна глава идёт через несколько уроков.

**Огласовки в «Кыраа рашида. Часть 2» доведены до конца книги.** Уроки 60–67
приходили огласованными на 24–41% против 99–100% в уроках 43–59 (перелом внутри
урока 60: первый рассказ полный, со второго — «Разговор о Луне» — голый
скелет). Так был размечен сам источник: сверка выгрузки с PDF кончалась на
`qr2-0285`, дальше оригинала у переводчика не было. Восемь уроков выгружены
обратно, огласованы и залиты назад: **99,6%**, согласный скелет не изменился ни
в одном фрагменте, перевод не тронут. Планка теперь держится тестом
(`tests/part2.test.mjs`), которого раньше у второй части не было — оттого просадка
и жила незамеченной при зелёном прогоне.

**Перезаливка идёт книгой, а не уроком.** Восемь уроков нельзя залить отдельно:
импорт кладёт книгу целиком на её же номера, под которыми лежит прогресс
ученика. Исходных выгрузок в репозитории нет, поэтому выгрузка книги была
собрана обратно из самих уроков, а исправленные восемь вклеены в неё. Проверка
такой сборки простая и обязательная: **уроки 43–59 после импорта должны совпасть
побайтно** с тем, что было. Так и вышло — все семнадцать.

- **Открывается по итоговому экзамену первой части.** Это и значит «набрал
  достаточно баллов»; пересдавать можно сколько угодно. Дальше уроки идут по
  порядку, и — как в первой части — пройденное не отнимается.
- **Урок в три шага.** Новые слова карточками (на обороте — фраза из текста,
  где слово встретится) → по одному заданию на слово → чтение всего текста.
  Урок засчитывается, когда прочитан текст: он здесь главный.
- **Задания строятся из данных, а не пишутся руками.** У каждой словарной
  единицы есть контекст; импортёр ищет в нём саму словоформу (снимая приставки,
  слитные местоимения и учитывая слабые корни) и кладёт её в `contextForm`.
  Нашлась — задание с пропуском на её месте; не нашлась — вопрос на смысл всей
  фразы. Сейчас 2928 и 362. Знаки препинания вокруг слова остаются во фразе, а
  не уезжают на кнопку ответа. Пропуск требует фразы: если контекстом стоит одно
  слово (заголовок рассказа, подпись), на экране остался бы голый прочерк —
  такое слово спрашивают на смысл. Дистракторы берутся из слов того же урока, сначала
  того же типа: глагол прячется среди глаголов.
  Артикль снимается даже с двухбуквенного остатка (`الْجَوّ` → `جَوّ`), одиночная
  приставка — только когда после неё остаётся три буквы: `ال` ничем другим быть
  не может, а одна буква вполне может принадлежать самому слову.
- **Повторение общее с первой частью.** Карточки второй части лежат в той же
  коробке `shifahiya-card-progress-v1` под адресом `p2-lesson-{id}-word-{i}-{dir}`,
  поэтому в ежедневной очереди слова обеих частей идут вперемешку, и недоученное
  из первой продолжает выходить.
- **Тексты второй части не повторяются по расписанию** — в отличие от чтения
  первой части. Текст большой, читается один раз внутри своего урока.
- **Импорт данных — по одной книге**:
  `npm run part2:import -- <словарь.json> <текст.json>`.
  Первый файл — накопительный словарь новых слов по урокам (он уже вычтен
  относительно первой части и всех предыдущих книг), второй — тот же формат пар,
  что и у чтения первой части, с заголовками рассказов отдельными строками.
  Как называется тип этой строки, каждая книга решала по-своему: `title`,
  `text_title`, `book_title`, `major_title`, `section_title`, `chapter_title` —
  все они озаглавливают кусок текста, все открывают рассказ. Строки `subheading`
  («(١) Часть 1») и `toc_item` (оглавление) размечают текст, но им не
  принадлежат — пропускаются со счётчиком. **Тип, которого скрипт не знает,
  останавливает импорт**: пропущенный незамеченным, он был бы прочитан ученику
  как предложение рассказа. Строки без арабских букв (номера страниц, одинокие
  точки) отбрасываются, и скрипт печатает, что именно отбросил.
- **Markdown из выгрузки снимается.** Цитата `>` в начале строки — и обратный
  слеш, которым markdown экранирует знак: `\-` это дефис, а прочитанный ученику
  слеш посреди арабской фразы — просто мусор. Таких мест было 82 во всей второй
  части, все в «Кыраа рашида. Часть 2», и ушли они вместе с её перезаливкой;
  тест теперь не пускает их обратно.
- **Название книги** берётся из `title` файла с текстом, а если оно начинается
  с «названия в кавычках» — из кавычек: у последних двух книг заголовок несёт
  сразу имя и подзаголовок, а над списком уроков нужно имя.
- **Книги ложатся одна за другой.** Каждая выгрузка нумерует свои уроки с
  единицы; импорт читает уроки, уже лежащие в `content/part2/`, и продолжает
  нумерацию за ними — урок 1 второй книги становится уроком 15 курса. Книга,
  уже загруженная, переимпортируется **на свои же номера**: под ними хранится
  прогресс ученика, поэтому сдвигать их нельзя. Если при этом изменилось число
  уроков, а за книгой уже лежат другие, импорт останавливается и называет те,
  которые надо перезалить следом. Манифест каждый раз пересобирается по курсу,
  а не по одной книге; тест требует сплошной нумерации и того, чтобы книга
  занимала один непрерывный кусок.
- **Рассказ, разорванный вёрсткой, собирается обратно.** Заголовок, повторённый
  после разрыва страницы, не начинает второй рассказ с тем же именем: внутри
  урока это тот же рассказ дальше, а за границей урока — «Разговор о Луне
  (продолжение)». Так же называются и куски текста, которыми урок начинается
  до всякого заголовка: это конец того, что читали в прошлом уроке, а не
  «Текст 1». Точка в конце заголовка снимается, строчная буква поднимается:
  это название урока на карточке, а не предложение.
- **Правки к выгрузке живут в скрипте, а не в данных.** Две таблицы в
  `scripts/import-part2.mjs`, каждая запись сверена с книгой:
  - `TEXT_FIXES` — строка, которую разметка поняла неправильно. Сейчас две:
    в `p2-s8-039` арабское название рассказа заменил номер страницы, и выгрузка
    приняла заголовок за обычную пару, отчего рассказ «Осёл и бык» терялся
    внутри соседнего (русское название уцелело — его хватает, чтобы рассказ
    открылся; арабское оставлено пустым, а не выдумано); `p3-s5-015`, наоборот,
    заголовком не является — `الشَّاعِرُ:` это вторая половина «как сказал поэт:»
    перед стихом, и как заголовок она разрывала надвое рассказ «Одежда».
  - `CONTEXT_FIXES` — слово, к которому подставлена чужая фраза. Сейчас одна:
    `جَوٌّ` («воздух») получило предложение про `الْجَوَابُ` («ответ») — слова лишь
    похожи на вид. Ключ — `source_id` пары, а не арабское слово: набранный
    руками арабский разойдётся с файлом в огласовках и не совпадёт ни с чем.
    Замена указывает на предложение того же урока, и арабский **вырезается** из
    него, а не печатается: огласовки тогда текстовы. Правка, переставшая
    совпадать, останавливает импорт, а не проходит молча.

  Перезалить исходники можно поверх — таблицы применяются на каждом импорте.

### Как добавить урок

1. Создать `content/lesson-NN.ts` (двузначный номер с ведущим нулём для 01–09),
   экспортировать `export const lessonNinetySix: Lesson = { ... }` — имя
   переменной прописью по-английски, `id` обязан совпадать с номером в имени файла.
2. Прогнать `npm run content:manifest` — урок сам подхватится глобом, ручной
   список импортов больше не нужен.
3. Добавить проверку в `tests/rendered-html.test.mjs` по образцу соседних уроков,
   там же поправить ожидаемое число файлов уроков.
4. Прогнать `npm test`.

**Арабский текст всегда с полной огласовкой (تشكيل)** — это учебный материал,
харакаты обязательны и в `decks`, и в `questions`.

**Ловушка с порядком огласовок.** Фатха + шадда и шадда + фатха выглядят
одинаково (`صَّ`), но это разные последовательности кодовых точек, и регулярка
в тесте не сработает. Нормальная форма (NFC) — сначала фатха (U+064E), затем
шадда (U+0651); файлы уроков в ней. Регулярку с арабской фразой не набирайте
руками — копируйте точную подстроку из файла урока.

Поле `description` пишется в формате `«N форм · 2 круга повторения · M заданий»`,
где `M = N * 2`. Число заданий относится к **итоговому** количеству после
автогенерации (см. ниже), а не к количеству авторских вопросов в файле —
расхождение с `questions.length` в исходнике нормально и ожидаемо. Число и
падежную форму («задание / задания / заданий») всё равно пересчитает
`expandLessonQuestions`, так что ошибиться в них не страшно — но в
`content/manifest.ts` попадает уже пересчитанное значение, поэтому после правки
урока манифест надо пересобрать.

- **Открывается по второй части целиком** — не по экзамену. Второй курс это сто
  пять уроков рассказов; научный текст читают после того, как рассказы читаются
  свободно, и обойти их нечем. `isPart3Open` смотрит, что у каждого урока второй
  части есть счёт. Дальше уроки идут по порядку, и пройденное не отнимается —
  как в обеих предыдущих частях.
- **Урок в те же три шага**, что и во второй части: новые слова карточками →
  по одному заданию на слово → чтение всего текста. Урок засчитывается, когда
  прочитан текст.
- **Задание спрашивает значение, а не форму в пропуске.** Словарь этой книги
  примеров не даёт («Контекстные примеры не приводятся»), и курс их не выдумал:
  на экране арабское слово, ответ — русский перевод. Обратное направление
  (русский → арабский) и так отрабатывается второй из двух карточек, которые
  кладёт каждое слово, а чтение направления не спрашивает вовсе. Дистракторы
  подбирает `buildOptions` первой части; вместо колоды ранжирование получает
  **тип слова** — термин прячется среди терминов, глагол среди глаголов.
- **Из текста ничего не вырезается.** Импортёру второй части приходится искать
  словоформу внутри фразы, чтобы поставить пропуск; здесь этого нет ни в
  скрипте, ни в данных. Причина не только в отсутствии примеров: книга спорит
  абзацами, а не предложениями — медиана фрагмента около тридцати слов, — и
  пропуск в абзаце проверял бы терпение, а не слово.
- **Фрагмент — единица выравнивания перевода**, поэтому он длиннее строки
  рассказа второй части. Резать его надвое ради вида нельзя: русская половина
  тогда перестанет соответствовать арабской.
- **Повторение общее с первыми двумя частями.** Карточки лежат в той же коробке
  `shifahiya-card-progress-v1` под адресом `p3-lesson-{id}-word-{i}-{dir}`,
  поэтому в ежедневной очереди слова всех трёх частей идут вперемешку.
- **Тексты третьей части по расписанию не повторяются** — как и во второй:
  текст читается один раз внутри своего урока.
- **Текущая версия текста — сверенная с оригиналом.** По сравнению с первой
  выгрузкой исправлено 325 русских фрагментов, восстановлено 18 арабских (в них
  коранические аяты были замещены нечитаемыми глифами шрифта — эти места ушли
  в первый релиз курса пустыми) и слит один фрагмент, дублировавший хвост
  соседнего из-за переноса страницы: 579 → 578. Позже перезалиты уроки 14 и 15,
  и разбитые в них блоки довели книгу до 686 фрагментов.
- **Правки к выгрузке живут в скрипте, а не в данных** — как во второй части.
  Три таблицы в `scripts/import-part3.mjs`, каждая запись сверена с текстом:
  - `TITLE_FIXES` — четыре урока, переименованных в сверенной редакции (4, 8,
    11, 20). Словарь заново не выгружали, и он держит прежние названия; сверка
    названий пропускает ровно эту пару строк и по-прежнему останавливает импорт
    на любом другом расхождении.
  - `TEXT_FIXES` — два места, по которым проехала сквозная замена самой
    редакции. Унификация حُدُوث на «возникновение во времени» верна, но задела
    خَلْق в заголовке пятого раздела (`مَسْأَلَةُ خَلْقِ الْقُرْآنِ` — это «сотворённость»,
    ровно то различие, которое та же правка и проводила, и название урока его
    держит), и оставила причастие в творительном падеже после вырезанного
    глагола.
  - `GLOSSARY_FIXES` — одно слово словаря, за которым текст ушёл вперёд:
    «таби'ины» с прямым апострофом при принятой в редакции системе «‘ — ‘айн,
    ’ — хамза».

  Правка, переставшая совпадать, останавливает импорт, а не проходит молча.
- **Баб берётся из словаря, а не из текста.** Сверенная редакция называет его
  «Часть первая», и для заголовков самой книги это верно, но не для этого
  экрана: приложение уже нумерует «Часть 1…3» три своих курса, и две шкалы
  читались бы как одна. Слово самой книги — «баб» — ни с чем не сталкивается.
- **Вторая книга пришла чистой.** 98–100% огласовки во всех семнадцати уроках,
  медиана фрагмента 25 слов, самый длинный — 55, битых глифов нет. Проверено тем
  же прогоном, что и первая книга, до импорта.
- **Уроки 14 и 15 первой книги перезалиты, и это закрыло сразу обе беды.** Они
  приходили набранными иначе, чем вся остальная книга: огласовано 40% и 69% слов,
  слова местами слипшиеся (`رواهالبخاري`), и там же лежали все девять фрагментов
  длиннее двухсот слов — 202–295, то есть по несколько страниц. Одна перезаливка
  дала **99% и 98%** огласовки, разбила блоки надвое по обеим сторонам сразу
  (максимум упал с 295 до 132 слов, число фрагментов выросло с 60 до 168) и убрала
  слипшиеся слова. Никаких исключений в тестах больше нет: планки держатся для
  всех тридцати семи уроков.
- **Крупные фрагменты не режутся на предложения на нашей стороне — ни скриптом,
  ни руками.**
  Проверено на данных: арабский ведёт длинные цепочки клауз через و/ف, а русский
  перевод рубит их на отдельные фразы, и число предложений у двух сторон
  сходится ровно в **одном фрагменте из двадцати семи** (в уроке 16 один
  арабский период даёт одиннадцать русских предложений). Нарезка по индексу
  предложения поэтому разъедет перевод с оригиналом — а молча прочитанный не тот
  перевод хуже длинного блока. Резать вручную по клаузам тоже не стоит: вне
  уроков 14 и 15 самый длинный фрагмент — 159 слов, это абзац, а не страница, и
  разрез оторвал бы аят от вводящей его фразы (`قَالَ اللهُ تَعَالَى: ﴿…﴾`). Там,
  где резать было нужно — уроки 14 и 15, — это сделал переводчик, по обеим
  сторонам сразу, и прислал перезалив.
- **Букву ё в этом тексте не выравнивают — решение автора, а не задача.**
  Редакция ставила ё там, где фрагмент правился по другой причине, поэтому
  одно и то же слово встречается в курсе и так, и так: **73 леммы написаны
  обоими способами**, 392 вхождения с ё против 396 без («всё» и «все» — 40 и 61,
  «чём» и «чем» — 25 и 51, «путём» и «путем» — 13 и 17). Восстанавливать ё не
  будем: на чтение это не влияет, а работа там ручная. Сквозной заменой она и не
  делается — все 16 вхождений «совершенн\*» здесь значат «полный, совершенный»
  («совершенная справедливость», «совершенными атрибутами», «совершеннолетний»),
  и слепой проход сделал бы из них «совершённый», то есть другое слово.

  Обратный проход — снять оставшиеся ё ради единообразия — тоже не делается, и
  по той же мерке: «всё» → «все» и «узнаём» → «узнаем» это потеря различения
  в пользу вида. Текст остаётся как есть.
- **Импорт данных — по одной книге**:
  `npm run part3:import -- <словарь.json> <текст.json>`.
  Первый файл — накопительный словарь по урокам (уже вычтенный относительно
  предыдущих частей и предыдущих книг), второй — фрагменты текста парами.
  **Книги ложатся одна за другой**, как во второй части: импорт читает уроки,
  уже лежащие в `content/part3/`, и продолжает нумерацию за ними — урок 1 второй
  книги становится уроком 21 курса. Книга, уже загруженная, переимпортируется
  **на свои же номера**: под ними хранится прогресс ученика. Если при этом
  изменилось число уроков, а за книгой уже лежат другие, импорт останавливается
  и называет те, которые надо перезалить следом. Манифест каждый раз
  пересобирается по курсу, а не по одной книге.
- **`TITLE_FIXES` ключуется по книге**, а не по одному номеру урока: каждая
  книга нумерует свои уроки с единицы, и голый номер перенёс бы правку из одной
  книги в другую. `TEXT_FIXES` и `GLOSSARY_FIXES` этого не требуют — их ключи
  это id фрагмента и слова, а они у книг разные (`hab-…`, `kur-…`).
- **Тип строки, которого скрипт не знает, останавливает импорт** — то же
  правило, что во второй части: пропущенная незамеченной, такая строка была бы
  прочитана ученику как предложение книги. Здесь текст сплошной, поэтому
  единственный допустимый тип — `pair`.
- **Названия уроков сверяются между двумя выгрузками.** Словарь и текст нумеруют
  одни и те же двадцать уроков; разошедшееся название значит, что файлы из
  разных редакций, и курс тогда учил бы слова к уроку, которого ученик не
  читает. Импорт в этом случае останавливается.
- **Название урока показывается и по-арабски** — так книга его и озаглавливает;
  на карточке оно стоит под русским (`.lesson-arabic-title`).

## Четвёртая часть курса

Ханафитский фикх по книге **«Тухфат аль-фукаха» («Подарок факихам»)** Аля
ад-Дина ас-Самарканди: **145 уроков, 923 новых слова, 4396 фрагментов текста.**
Загружены восемь книг фикха подряд — от очищения до развода.

| Книга фикха | Уроки | Слов | Фрагментов |
|---|---|---|---|
| Книга очищения | 1–12 | 185 | 635 |
| Книга намаза (с похоронными обрядами) | 13–34 | 187 | 682 |
| Книга закята | 35–52 | 100 | 508 |
| Книга поста | 53–62 | 40 | 300 |
| Книга хаджа | 63–80 | 75 | 472 |
| Книга торговли | 81–114 | 131 | 864 |
| Книга никаха | 115–119 | 41 | 141 |
| Книга таляка | 120–145 | 164 | 794 |

- **Устроена ровно как третья часть** — словарь и текст, три шага урока, задание
  на значение слова, — поэтому она не завела ни своих типов, ни своего движка
  заданий, ни своих экранов. Форма урока называется `TextCourseLesson`, задания
  строит `content/text-course-questions.ts`, общие правила доступа лежат в
  `app/text-course-access.ts`, а `app/page.tsx` ведёт обе части одним набором
  экранов (`text-learn | text-practice | text-reading | text-result`).
  Своё у каждой части — данные, гейт и адрес карточки (`p3-` и `p4-`).
- **Открывается по третьей части целиком** — как третья по второй, и по той же
  причине: между ними нет работы, есть тридцать семь уроков научного текста.
  Книга фикха спорит там, где книга по акыде утверждала: ставит вопрос, взвешивает
  чужие мнения и решает, — и читается это после того, как читается научная
  страница. `isPart4Open` смотрит, что у каждого урока третьей части есть счёт.
- **Урок может не приносить новых слов** — таких двенадцать (29, 31, 50, 55, 59,
  80, 95, 99, 101, 104, 114, 126). Словарь накопительный **против всех трёх
  предыдущих частей**, и в глубине книги урок вправе не встретить ничего нового.
  Такой урок — это его текст: ни карточек, ни заданий, он открывается сразу на
  чтении, а на главной вместо «0 новых слов» написано «только чтение». Прогон в
  браузере проверяет это отдельно от обычного урока.
- **Двадцать шесть уроков приносят одно-два слова**, и из своих слов такой урок
  не набрал бы трёх вариантов ответа. Тогда неверные варианты берутся из
  **пройденного** — из слов уроков до этого, — и никогда из тех, что впереди:
  вариант прочитывают прежде, чем отвергнуть, и курс не показывает значения,
  которого не давал. Весь словарь курса лежит в `content/part4/glossary.ts` и
  грузится своим чанком **только теми уроками, которым он нужен**.
- **Два уровня деления книги разведены по разным местам.** Выгрузка держит их в
  одном поле через `·`: «Книга очищения · Глава о хадасе». Кита́б (восемь на всю
  книгу) идёт в `section` и озаглавливает кусок списка; баб (шестьдесят с лишним)
  идёт в `chapter` и написан на карточке урока — разделитель через урок мешал бы
  читать список, да и один и тот же баб в книге намаза встречается дважды, так
  что в разделители он не годится по существу. Тест требует непрерывности
  кита́ба и ничего не требует от баба. Книги никаха и таляка второго уровня не
  несут вовсе, и выдумывать его для них не станем — карточка их уроков просто
  без главы.
- **Заголовок внутри урока остаётся заголовком.** В тексте 77 таких строк; они
  несут обе стороны и лежат во фрагментах с пометкой `heading`, а на экране
  чтения набраны иначе (`.reading-line.is-heading`). Проглотить пометку значило
  бы прочитать ученику заголовок как фразу книги — ровно то, от чего защищаются
  импортёры второй и третьей частей. В выгрузке такая строка называется
  `section` в первых шести книгах и `heading` в следующих; обе озаглавливают
  кусок текста, обе открывают его.
- **Разметку, которая тексту не принадлежит, импорт пропускает со счётчиком.**
  Таких строк три вида: `divider` — линейка на странице, `note` — примечание
  переводчика о печатном оригинале (по-русски, без арабского) и `term` —
  подстрочное толкование арабского термина. Терминов 32; **27 из них и так
  лежат в накопительном словаре**, которым курс их и учит, а на экране чтения
  ученик нажимает строку за переводом, а не за словарной статьёй. Пропущенные
  строки печатаются числом при каждом импорте, так что вернуть их — это одна
  правка в `SKIPPED_ROWS`, а не поиск потери.
- **Повторение общее со всеми частями.** Карточки лежат в той же коробке
  `shifahiya-card-progress-v1` под адресом `p4-lesson-{id}-word-{i}-{dir}`.
  Тексты по расписанию не повторяются — как во второй и третьей части.
- **Выгрузка пришла чистой.** Первые шесть книг: 99,6% огласовки (слабейший
  урок — 114-й, 94%), медиана фрагмента 22 слова, самый длинный — 113. Никах и
  таляк — **100%** огласовки, медиана 17 слов, самый длинный — 48. Битых глифов
  нет, слипшихся слов нет, названия уроков в словаре и тексте сошлись все 145.
  Проверено тем же прогоном, что и книги третьей части, до импорта.
- **Правки к выгрузке живут в скрипте, а не в данных** — как в предыдущих частях.
  Сейчас правка одна: `GLOSSARY_FIXES` огласовывает слово `ساج` («тиковое
  бревно»), пришедшее голым скелетом, по тому, как оно набрано в самом тексте
  урока 98 — `سَاجَةً`. Правка, переставшая совпадать, останавливает импорт.
  `TITLE_FIXES` и `TEXT_FIXES` пустые: обе выгрузки из одной редакции. Таблицы
  оставлены, потому что расхождения появляются при перезаливке, а не сейчас.
- **Импорт данных — по одной книге**:
  `npm run part4:import -- <словарь.json> <текст.json>`.
  Правила те же, что в третьей части: книги ложатся одна за другой, уже
  загруженная переимпортируется на свои же номера, манифест пересобирается по
  всему курсу. Незнакомый тип строки останавливает импорт.
- **Выгрузка текста приходит в двух видах, и скрипт понимает оба.** Первая
  клала все строки книги в один `items[]`, где каждая говорит свой урок;
  следующие вкладывают строки в урок — `lessons[].blocks[]`. Строки при этом
  одни и те же, поэтому `rowsOf` читает любую форму в один список.
- **«Тухфат аль-фукаха» — одна книга, и заливается она целиком.** Продолжение
  приходит отдельными файлами (никах, таляк), но импорт кладёт книгу на её же
  номера, под которыми лежит прогресс ученика, поэтому файлы сначала
  склеиваются в одну выгрузку на все уроки. Проверка склейки обязательна и
  простая: **уроки, которых продолжение не касалось, должны совпасть побайтно**.
  При заливке никаха и таляка так и вышло — все 114.

## Пятая часть курса

Грамматика по двум книгам сразу: **105 уроков, 479 новых слов, 4045 фрагментов
текста.** Урок сарфа и урок нахва идут через один — нечётные номера это
«Тайсир ас-сарф», чётные «Ан-Нахв аль-вадых».

| Книга | Уроки | Слов | Фрагментов |
|---|---|---|---|
| Тайсир ас-сарф | нечётные, 53 урока | 177 | 1605 |
| Ан-Нахв аль-вадых | чётные, 52 урока | 302 | 2440 |

- **Это не та грамматика, которую выключили.** `GRAMMAR_ENABLED = false`
  относится к грамматическим блокам внутри уроков первой части — авторскому
  разбору, написанному для «Шифахии». Здесь другое: две настоящие книги,
  переведённые целиком, и читаются они так же, как книги третьей и четвёртой
  частей. Старое решение остаётся в силе и этой части не касается.

ибн Шарафа ан-Навави ад-Димашки (631–676 г. х.): **46 уроков, 183 новых слова,
1119 фрагментов текста.** Одна книга, и делит она себя сама:

| Раздел | Уроки |
|---|---|
| Предисловие | 1 |
| Хадисы 1–14 | 2–15 |
| Хадисы 15–28 | 16–29 |
| Хадисы 29–42 | 30–43 |
| Огласовка трудных слов | 44–45 |
| Заключение | 46 |

- **Открывается по девятой части целиком** — цепочка, по которой открывается
  каждая часть здесь. Сорок хадисов идут последними в чтении не по трудности:
  девять частей до них учат языку и наукам, которые взвешивают сообщение и
  решение, а это и есть тот матн, о котором те науки говорят. Его читают, когда
  ученик слышит, что именно взвешивают.
- **Каждый урок приносит новые слова** — как в шестой части: матн короткий, и у
  каждого хадиса своя лексика. Четырнадцать уроков приносят одно-два слова и
  добирают неверные варианты из пройденного, тем же способом, что и раньше.
- **Уроки 44–45 — авторские указания к огласовке**, а 46 — заключение и колофон.
  Это части самой книги, и они читаются как её текст; отдельного обращения им
  не потребовалось.
- **Заголовок внутри урока остаётся заголовком.** Их 183 — номер хадиса и имя
  того, что разбирается; `section` для внешнего уровня, `heading` для
  внутреннего, как в книгах восьмой и девятой частей. Линейка (`divider`) —
  45 строк — пропускается со счётчиком.
- **Огласовка доведена до конца, и это единственное, что потребовало работы.**
  Первая выгрузка пришла на **83,1%**: знаменательные слова огласованы, а
  служебные — `في`, `ما`, `لا`, `الله`, формула `رضي الله عنه` — нет. Планку в 85%
  не проходили **37 уроков из 46**, лучший во всей книге давал 92%. Это тот же
  случай, что уроки 60–67 второй части и 14–15 третьей, и решён он так же:
  выгрузка возвращена переводчику с пометками у каждого блока, где есть работа
  (`_огласовать` и `_голые`), и залита исправленной. Стало **100%**, и сверка
  дала то, что и требуется от перезаливки: **согласный скелет не изменился ни в
  одном из 1164 блоков, перевод не тронут, блоки не потерялись и не добавились.**
  Служебные поля выгрузки импорт игнорирует — в данные они не попали.
- **`p10` — первый двузначный префикс карточки**, и это стоит помнить: адреса
  повторения читаются регуляркой `^p{N}-lesson-`, поэтому чужая карточка в свою
  часть не попадёт, а своя не потеряется. Проверяется машинно, в обе стороны для
  всех семи текстовых частей до неё (`tests/part10.test.mjs`), и прогон в
  браузере отдельно смотрит гейт: вкладка закрыта, пока девятая не пройдена
  целиком, и открывается, когда пройдена.
- **Импорт данных**: `npm run part10:import -- <словарь.json> <текст.json>`.
  Выгрузка текста приходит файлом `data.js`, как в восьмой и девятой частях.

### Общая машинерия импорта

Части с четвёртой по десятую импортируются одним модулем —
`scripts/text-course-import.mjs`. Нумерация, манифест, чанк словаря, сверка
названий между двумя выгрузками, правило «незнакомый тип строки останавливает
импорт», перезаливка книги на её же номера — всё это одно и то же, и третья
копия этого кода разошлась бы с оригиналом при первой же правке. В скрипте
части остаётся только её собственное: как её выгрузка называет вещи, на какие
уровни делится книга и какие правки к ней применяются. Шестая, седьмая и
восьмая части стоили ровно этого: конфиг на полсотни строк, загрузчик, гейт и
тест. Восьмая добавила к общему модулю ещё три вещи, и все три — свойства
выгрузки, а не курса: как называется строка самого текста (`pairRows`), строка
стиха (`verseRows`) и строка, которую пропускают по имени (`SKIPPED_IDS`).
**Ни девятая, ни десятая не добавили ничего** — их выгрузки пришли в той же
форме, что у восьмой, и конфиг каждой свёлся к данным, названию книги и делению
на разделы.

Проверка при выносе была та же, что при перезаливках: **после рефакторинга
импорт четвёртой части дал те же 145 файлов уроков и тот же словарь побайтно** —
изменился только комментарий в шапке манифеста.

**Выгрузка текста приходила уже в пяти видах**, и модуль читает любой:
плоский `items[]`; `lessons[].blocks[]`; заголовки уроков отдельно от строк
(`lesson_blocks[]`); в последней книге логики — вложенный заголовок,
`lessons[].lesson.number`; и в книгах хадиса — снова `lessons[].blocks[]`, но с
названиями `titleRu`/`titleAr` и типом `text` вместо `pair`. Название урока
модуль ищет во всех трёх написаниях. Это разница выгрузок, а не курсов, поэтому
живёт в общем модуле, а не в конфиге части: после этого `titleOf` понадобился
только пятой части, где заголовок урока — не заголовок исходной книги.

## Подкаст дня

Вторая привычка рядом с курсом: **один арабский подкаст в день**. Отдельный
маршрут `/podcasts`, отдельное хранилище, отдельная серия. Причина, по которой
это не часть курса: просмотр подкаста — не урок. Он ничего не открывает, не
влияет на счёт урока и не кладёт ни одной карточки в коробки Лейтнера. Смешать
их — значит либо обесценить урок, либо превратить просмотр в обязанность.

- **Цель дня — один выпуск, максимум не ограничен.** Отсюда главное разделение
  всей функции: «цель выполнена» и «сколько просмотрено» — разные величины.
  День в календаре либо зелёный, либо нет; второй и пятый выпуск двигают только
  счётчики. Иначе хороший день задним числом делал бы вчерашний день неудачей.
- **Выпуск закреплён за датой.** `planForDay` в `app/podcast-day.ts` выбирает
  детерминированно — `seededShuffle` с сидом от строки даты, тот же механизм,
  что у дистракторов. **Нет даты — нет выпуска:** сервер не знает часового пояса
  ученика, и выбранный там выпуск клиент тут же заменил бы другим, то есть ровно
  тем, против чего закрепление и сделано. Пока `today` пуст, карточки нет;
  `tests/podcasts.test.mjs` проверяет, что в серверной разметке её и не бывает. Перезагрузка страницы выпуск не меняет: привычку легче
  держать, когда дело уже решено, а свежий случайный ролик на каждый F5
  превращает приложение в игровой автомат. Поменять выпуск можно только руками —
  кнопкой «Другое», и отвергнутый уходит в `skipped` до конца дня.
- **Закреплённый выпуск не открепляется после просмотра.** Иначе карточка
  перестала бы показывать то, что ученик только что досмотрел. Открепляет его
  только исчезновение из каталога или выход за окно длительности.
- **Карточку показывает непросмотренность текущего выпуска, а не невыполненная
  цель.** Разница видна только на «Посмотреть ещё»: цель остаётся выполненной
  до конца дня, поэтому условие по цели прятало бы карточку навсегда — второй
  выпуск закреплялся бы и не показывался. Повторное нажатие при уже
  закреплённом непросмотренном выпуске ничего не закрепляет: иначе клики
  проматывали бы каталог.
- **Окно длительности — 5–15 минут** по умолчанию (`DEFAULT_WINDOW`),
  переключается в настройках до 60 минут. Нижняя граница отсекает шортсы,
  верхняя — то, что откладывают на завтра.
- **Два способа отметить просмотр, и они не равнозначны.** Встроенный плеер
  измеряет: `app/youtube-embed.ts` опрашивает позицию и засчитывает день на 80%
  (`WATCHED_RATIO`). **Засчитать — не значит прекратить:** отметка не гасит
  плеер, иначе у каждого выпуска отнималась бы последняя пятая часть. Карточка
  живёт, пока идёт просмотр, даже когда выпуск уже в счёте, и закрывается сама
  по концу ролика. Ручная отметка, наоборот, плеер закрывает: её ставят, когда
  смотрят не здесь. Просмотр в приложении YouTube измерить нельзя вообще —
  YouTube не даёт стороннему приложению доступа к истории просмотров, — поэтому
  там кнопка «Я посмотрел» и доверие к ученику. Оба честны, автоматический
  только один. Рядом лежит «Отменить отметку»: промахнуться легко.
- **Один и тот же выпуск не засчитывается дважды.** `markWatched` молча выходит,
  если `videoId` уже в журнале, — иначе двойное нажатие раздуло бы и число
  выпусков, и минуты.
- **День — местный.** `podcastDate` берёт полдень локального времени, а не UTC:
  вечер в часовом поясе восточнее Гринвича иначе уехал бы на следующий день.
  `todayStore` — второй внешний стор: сервер отдаёт пустую дату (он не знает
  часового пояса ученика), а подписка перевзводится в полночь, поэтому
  оставленная на ночь вкладка сама переходит на новый день.
- **Серия не рвётся незаконченным сегодня.** `streaks` считает серию живой, пока
  последний активный день — сегодня или вчера: день не потерян, пока не кончился.
  По той же причине сегодняшняя клетка календаря — своё состояние `today`, а не
  «пропущено».
- **Заметка «ماذا فهمت؟»** — необязательное поле после просмотра. Оно превращает
  пассивный просмотр в практику, но ничего не требует и ни на что не влияет.

### Откуда берётся список выпусков

Сайт — статические файлы, сервера нет, а значит, некому сходить в YouTube в
момент открытия страницы. Отсюда два пути, и они дополняют друг друга:

1. **При сборке.** `YOUTUBE_API_KEY=… npm run podcasts:import` читает каналы из
   `content/podcasts/channels.ts` и переписывает `content/podcasts/catalog.ts`.
   Файл коммитится и едет вместе с сайтом — тогда ключ не нужен никому.
2. **С устройства.** Ключ YouTube Data API, введённый в настройках экрана,
   позволяет приложению обновить список самому; копия ложится в `localStorage`.
   `activeCatalog` выбирает свежайший из двух по `generatedAt` и **никогда** не
   заменяет собранный при сборке список пустым результатом обновления.

**Обновляется раз в неделю через pull request.** `.github/workflows/podcasts.yml`
по понедельникам гоняет импортёр с секретом `YOUTUBE_API_KEY`, прогоняет тесты и
предлагает свежий каталог отдельным PR из ветки `podcasts/refresh`.

Почему PR, а не push: `main` защищена ruleset'ом «protect main branches» с
правилом «изменения только через pull request», а выдать GitHub Actions bypass
в нём нельзя — в списке bypass нет такого актора (проверено: вкладки Apps и
Others пусты). Прямой push от `GITHUB_TOKEN` отклоняется с `GH013`.

Так оказалось даже уместнее: в диффе видно, какие выпуски добавились, а мерж —
обычный push человеком, поэтому `deploy.yml` запускается сам, без всякого
`workflow_call`. Ветка одна и постоянная, и переписывается force-push'ем:
непримёрженное обновление прошлой недели должно замещаться свежим, а не
копиться отдельными PR. Если PR уже открыт, новый не создаётся — обновляется
тот же, **и тело переписывается вместе с веткой**: написанное только при
создании, оно продолжало описывать обновление, которое давно вытеснено
force-push'ем, — открытый PR говорил про 421 выпуск, когда в ветке лежало 394.
Тесты идут до создания ветки: каталог — это то, что приложение
показывает ученику. Не изменился — ни ветки, ни PR;
сравнение идёт с `git diff -I '^  generatedAt: '`, потому что время сборки
штампуется заново каждый импорт и обычный diff не бывает пустым — неделя без
новых выпусков всё равно открывала бы PR на одну строку.

**Тело PR пишет сам импортёр**, а не задание. Задание считало выпуски и каналы
`grep`'ом по сгенерированному файлу — что там есть, то и сосчиталось, а вот
чего там не стало, `grep` увидеть не мог. Поэтому импортёр, который один и знает
про пропавший канал, пишет разметку в `PODCAST_SUMMARY_FILE`, а задание отдаёт
её как `--body-file`. При ручном запуске переменная не задана, и файла не
появляется.

**Канал, не ответивший на обновление, называется в теле PR вместе с ценой.**
Импорт его по-прежнему пропускает — правило «одно переименование не стоит
ученику двух других каналов» в силе, — но раздел «Канал не открылся» говорит,
сколько выпусков этого канала лежит в каталоге **сейчас** и потому уйдёт при
мерже, и что хендл поправляется в `content/podcasts/channels.ts`. Ровно так один
канал однажды и вышел из каталога незамеченным: предупреждение ушло в лог
задания, а PR о нём молчал.

**В каталоге сейчас 408 выпусков трёх каналов** (собран 31.08.2026). Пустым он
тоже бывает — до первого импорта, — и тогда экран честно это объясняет и
предлагает оба пути, а не делает вид, что выпуски кончились.

- **Списки берутся из плейлиста загрузок канала, а не поиском.** `search.list`
  стоит 100 единиц квоты, страница `playlistItems.list` — 1, при дневном лимите
  10 000. Разница между сотней обновлений в день и сотней обновлений в день на
  всю оставшуюся жизнь.
- **Длительность читается из API, а не угадывается по названию** — `videos.list`,
  поле `contentDetails.duration` в формате ISO 8601 (`PT11M42S`). Неразобранная
  длительность даёт 0 и отсекается фильтром: выпуск неизвестной длины лучше не
  предлагать.
- **В каталог кладётся более широкий диапазон, чем окно просмотра** (60 секунд —
  60 минут), чтобы расширение окна в настройках не требовало переимпорта.
  Идущие и анонсированные трансляции пропускаются: у них нет длительности.
- **Канал, который не открылся, пропускается с предупреждением**, а не роняет
  весь импорт: одно переименование не должно стоить ученику двух других каналов.
  Отказ по ключу, наоборот, роняет всё — продолжать с ним нечего.
- **Ключ ученика — его дело.** Лежит в `localStorage`, уходит только на
  `googleapis.com`. Своего сервера у проекта нет, и кода, который бы отправил
  ключ куда-то ещё, быть не должно: `tests/podcasts.test.mjs` проверяет машинно,
  что в `app/podcast-youtube.ts` нет ни одного постороннего хоста.
- **Ссылка на канал разбирается терпимо, но не угадывается.** `parseChannelHandle`
  понимает полный адрес с трекингом, `@handle` и голое имя, приводя всё к
  `@нижнему регистру`. Адреса `/channel/UC…`, `/c/Name`, `/user/Name` дают пустую
  строку: в них нет handle, и принять путь за handle — значит молча добавить
  несуществующий канал.

### Хранилище подкастов

Своё, не смешанное с курсовым: ключи `shifahiya-podcasts-v1` (журнал просмотров),
`shifahiya-podcast-days-v1` (закреплённые выпуски), `shifahiya-podcast-catalog-v1`,
`shifahiya-podcast-sources-v1`, `shifahiya-podcast-window-v1`,
`shifahiya-podcast-key`. Читается тем же `useSyncExternalStore`, что и прогресс
курса. Планы старше 30 дней подчищаются — журнал просмотров и есть та запись,
которую стоит хранить.

**Синхронизация между устройствами общая с курсом.** `app/sync.ts` возит один
payload — прогресс курса плюс поле `podcasts`, — а `mergeSynced` в
`app/merge-progress.ts` сливает обе половины. Payload, записанный до этого,
просто не имеет поля `podcasts`, и `normalizeSynced` его подставляет пустым.

Что ездит и по каким правилам:

- **журнал просмотров** — объединение по `videoId`. Один и тот же выпуск,
  засчитанный на двух устройствах, остаётся **одним** просмотром и датируется
  первым зачётом: иначе раздулись бы и число выпусков, и минуты. Заметка
  выбирается из текста, потому что времени у неё нет: непустая бьёт пустую,
  длинная — короткую, равные решаются сравнением (ничего по существу не
  решает, но решает одинаково на обоих устройствах);
- **планы дня** — по дате; побеждает тот, где выпусков закреплено больше,
  а `skipped` объединяются: отвергнутое на любом устройстве отвергнуто;
- **каналы** — объединение.

Что **не** ездит: окно длительности — у него нет отметки времени, и угадывать,
какая из двух настроек новее, значит молча менять то, что ученику предлагают.
Ключ YouTube не ездит никогда: это учётные данные, а не прогресс.

Слияние коммутативно, это проверяется тестом — как и у курса.

## Темы наизусть

Третья дверь рядом с курсом и подкастами: **тема из своей книги, разобранная до
фактов и возвращаемая по расписанию, пока не останется в памяти.** Отдельный
маршрут `/topics`, отдельное хранилище, отдельные правила. Темы идут в порядке
книг, из которых взяты:

- **Текста книги здесь нет, и это главное условие.** Ученик читает раздел по
  своей книге; приложение даёт то, чего чтение не даёт, — вопросы, которые
  заставляют вспомнить, расчёт по таблицам темы и расписание. Поэтому у каждого
  занятия стоят страницы книги, а у каждого вопроса — своя страница: ответ на
  экране должен проверяться по оригиналу в одно движение. Тест это и требует —
  страница вопроса обязана попадать в диапазон раздела.
- **Единица — не карточка со словом, а вопрос.** `Atom` бывает двух видов: `fact`
  (один ответ) и `list` (перечисление, которое должно вернуться целиком).
  Списком идёт всё, что книга сама перечисляет: условия обязательности, восемь
  групп получателей закята, фарды и ваджибы хаджа, столпы наследования.
- **Список проверяется по пунктам, а не «да/нет».** Ученик вспоминает вслух,
  открывает список и отмечает то, что действительно назвал; оценку ставит
  `gradeFromRecall` — всё названо «вспомнил», половина и больше «с трудом»,
  меньше половины «не вспомнил». Половина списка — обычное состояние памяти, и
  карточка, которая этого не видит, учит соглашаться на половину.
- **Форма вопроса зависит от коробки.** `modeFor`: список — всегда список
  (выбрать перечисление из четырёх вариантов нельзя, оно само и есть ответ);
  факт с написанными вариантами — выбор, пока карточка новая или только что
  забыта, дальше свободное припоминание. Узнавание — опора на первый день, а не
  способ сдавать на десятый.
- **Неверные варианты написаны руками, а не подобраны.** Ровно там, где спутать
  есть что: 85 г против 595 г, одна десятая против одной двадцатой, фард против
  ваджиба. Подбирать дистракторы к прозе автоматически — значит предлагать
  ученику отвергать бессмыслицу; у 28 фактов из 68 варианты есть, остальные
  спрашиваются свободно.
- **Три оценки, а не «верно/неверно».** `again` возвращает карточку в начало и
  считается потерей (`lapses`), `hard` держит интервал, `good` двигает дальше.
  Забытое переспрашивается **в той же сессии**: не вспомненный вопрос
  дописывается в конец очереди.
- **Коробки свои**: `TOPIC_INTERVALS = [0, 1, 3, 7, 16, 35, 90]`. Первые четыре
  закрывают неделю, в которую теряется почти всё; последняя — квартал: тему учат
  не к дате, а чтобы знать. В курсовые коробки Лейтнера ничего из этого не
  попадает — это проверяется тестом и прогоном в браузере.
- **Уже известное можно сразу убрать из коротких повторений.** После показа
  ответа каждая из семи форм вопроса даёт кнопку «Выучил»: она переносит единицу
  прямо в последнюю коробку на 90 дней и удаляет её возможные повторы из остатка
  текущей очереди. Это не вечное исключение — через квартал вопрос вернётся.
  Итог занятия считает такие единицы отдельно.
- **Таблицы не заучиваются, а считаются.** Книга сама спрашивает «26 верблюдов —
  ?», «190 овец — ?», поэтому у темы есть тренажёры. Их шесть видов:
  `steps` — ступенчатая таблица (верблюды, коровы, овцы), `share` — доля урожая
  (одна десятая против одной двадцатой), `money` — деньги против нисаба (85 г
  золота по названной в задании цене), `sort` — разбор на кучки, `order` —
  порядок обряда и `estate` — раздел наследства. Число, набор и окно в задании каждый раз другие: они выводятся
  из сида (`taskSeed` от id, даты и числа повторений), поэтому запомнить ответ
  нельзя, можно только уметь. Тренажёр — такая же карточка расписания, как факт.
- **Кучек у разбора две или три.** Фикх сортирует по трём (фард, ваджиб, сунна;
  жертвоприношение, садака фитр, горсть пшеницы) не реже, чем по двум, и пара
  кучек разломила бы такой материал надвое. В задание обязательно попадает по
  одной из каждой кучки, если в нём есть для них место: задание, тихо потерявшее
  третье правило, учит, что правил два.
- **Порядок спрашивается окном, а не целиком.** Обряд — это последовательность,
  и знать его части не значит знать их порядок. В `order` хранится весь порядок,
  а задание берёт из него подряд идущие шаги и перемешивает их; перемешивание,
  случайно совпавшее с ответом, перебрасывается — задание, ответ на которое
  и есть вопрос, не проверяет ничего.
- **Зачёт — вопросы книги, и ни одного своего** (27 у закята, 70 у паломничества). Эталон ответа
  собирается из тех же атомов, а не пишется второй раз: две копии одного правила
  Эталон ответа собирается из тех же атомов, а не пишется второй раз: две копии
  одного правила разойдутся на первой же правке. Оценка своя, из трёх: «ответил»
  ничего не меняет, «частично» опускает факты вопроса на коробку ниже,
  «не ответил» возвращает их в начало. Проходной балл — тот же, что у экзаменов
  курса (`examPassMark`): 22 из 27 и 54 из 70. **Зачёт открывается, когда
  разобраны все занятия темы**, и ничего не закрывает: слабая попытка не
  отнимает ни занятия, ни прежнего результата.
- **Занятия не заперты друг за другом.** Ученик читает свою книгу сам и вправе
  начать с любого места; курсовая цепочка «часть за частью» здесь ни при чём.
  Заперт только зачёт — он по всему разделу.
- **Сессия зачёта не сохраняется, и это осознанно.** Действие на карточки
  применяется сразу после каждого вопроса, поэтому прерванный зачёт уже сделал
  свою работу; теряется только счёт текущей попытки.
- **Синхронизация общая с курсом и подкастами.** `app/sync.ts` возит третье поле
  `topics`, `mergeTopics` в `app/merge-progress.ts` сливает его: карточка — та,
  где позже `lastSeen` (дальше по коробке, затем по числу ответов), потери
  считаются по максимуму, занятие — по более ранней дате (разобрано значит
  разобрано), зачёт — лучший балл, большее число попыток, дата первой сдачи.
  Слияние коммутативно, как и у курса.
- **От книги не отходят, а несходящееся помечают.** Тема говорит то, что
  говорит книга, — и там, где книга не сходится сама с собой (одно правило в
  двух видах, номер аята, напечатанный двумя способами, вопрос о том, чего в
  её же перечне нет), карточка держит книжное, а рядом с ответом стоит знак
  «?»: по нажатию открывается, что именно не сошлось и на какой странице.
  Решает такое место автор темы по оригиналу, а не тот, кто мимо проходил, —
  поэтому пометка сообщает, а не советует. Поле — `check` у атома и у вопроса
  зачёта, знак рисует `CheckMark` в `app/topics/page.tsx`. Сейчас помечено
  тридцать мест, их список закреплён тестом, а прогон в браузере проверяет, что
  знак доходит до экрана и открывается.
- **Тема дописывается главами, и это ничего не сдвигает.** Адрес карточки —
  `тема:единица`, а не её место в списке, поэтому новая глава дописывается в
  `steps`, а её вопросы — в конец зачёта, не трогая ни одной карточки,
  которая уже лежит у ученика в расписании. Это то же правило, по которому
  наращивается урок курса, только здесь оно дано даром: там адрес карточки
  позиционный, здесь — именной.
- **Первый раздел «Стилистики» сверен по книге целиком.** Все 16 карточек стоят
  на своих печатных страницах (8–11), арабские названия трудов прочитаны с
  картинки и совпали с книгой до огласовки, а знак «?» у списка учёных
  подтвердился печатью: книга действительно передаёт `الْكَشَّافُ` по-русски как
  «Лампа». Карточка держит книжное и называет расхождение — решает его автор
  темы, а не тот, кто мимо проходил.
- **Полка сгруппирована по книгам, а не по темам.** Книга, разобранная по
  разделам, приходит сюда несколькими темами — пять у «Мухтасар аль-Кудури»,
  четыре у «Стилистики арабского языка», — и каждая печатала имя книги на своей
  карточке. `TOPIC_BOOKS` в `content/topics/catalog.ts` собирает полку в
  непрерывные куски по `source.book`, экран ставит над куском один разделитель
  (`.book-divider`, тот же, что у списков курса), а карточка под ним говорит
  только свой раздел и страницы. **Группа — непрерывный кусок, а не имя:** если
  та же книга вернётся ниже по полке вторым томом, она озаглавит своё место, а
  не будет молча поднята к первому — иначе полка переставилась бы под учеником.
- **Раздел, по которому книга не даёт вопросов, зачёта не показывает.** Это то
  же правило «зачёт — вопросы книги, и ни одного своего», доведённое до конца:
  у «Ясных разъяснений» и у первого раздела «Стилистики» списка вопросов в книге
  нет, и карточка зачёта предлагала работу из нуля вопросов с проходным баллом
  1 — `examPassMark(0)`. Начать её было нельзя, сдать тоже. Теперь её просто нет.
- **Главный экран знает только число.** `app/page.tsx` читает из хранилища тем
  сколько вопросов ждёт сегодня и рисует счётчик на ссылке — не больше.
  Содержимое тем в стартовый чанк не попадает, и тест это проверяет: повторение
  темы не влияет ни на счёт урока, ни на коробки, ни на статистику курса.

### Паломничество — что в этой теме своего

- **Раздел втрое больше закята**, и потому занятий четырнадцать, а не восемь.
  Дробить его на две темы не стали: книга держит его одним разделом, и зачёт в
  ней тоже один — семьдесят вопросов на весь материал.
- **Хадж — это последовательность**, и она спрашивается порядком: `drill-order`
  хранит одиннадцать шагов хаджа Ифрад, от ихрама в микате до прощального
  тавафа, а задание берёт из них окно в пять шагов.
- **Разбор по трём кучкам понадобился дважды**: фард, ваджиб, сунна (вопрос 4
  самой книги) и три ступени искупления — жертвоприношение, садака фитр, горсть
  пшеницы (вопросы 39–48). Второй разбор и есть самая трудная часть раздела:
  нарушение одно и то же, а искупление зависит от меры — сколько времени, какая
  часть, какая площадь ткани.
- **Пара «фард — ваджиб» проверяется там, где её путают.** Стояние на Арафате
  фард, а стояние до захода солнца — ваджиб; обе строки лежат в одном разборе.
- **Где книга обрывает фразу, мы её не дописываем.** В просрочке действий второй
  случай — подстригание волос после дней праздника — назван без искупления;
  атом говорит ровно это, а знак «?» рядом сообщает, что фраза на с. 130
  оборвана. Придумать за книгу — то же, что переврать её.

### Наследственное право — что в этой теме своего

- **Это вторая книга**: Р.М. Нургалеев, «Наследственное право в исламе» (Казань,
  ДУМ РТ, 2009). Издание и оговорки к теме стоят в `source.note` и показываются
  на её экране под вступлением — на карточке списка нужно только имя книги.
- **Книга разобрана целиком, с. 7–129** — четыре главы, словарь терминов,
  104 вопроса книги. Росла она главами, и **ни одна карточка прежних глав ни
  разу не сдвинулась**: на каждой заливке всё, что уже лежало, сверялось
  побайтно по своим id, а вопросы зачёта — по местам и номерам. Так пришли
  вторая глава (к 39 атомам первой), третья (к 134) и четвёртая (к 196). Это и
  есть та проверка, ради которой адрес карточки именной: сверка старого и
  нового файла до установки, а не после жалобы ученика. Команда сверки записана
  в `docs/topic-authoring.md`.
- **Книга спрашивает сама после каждого подраздела**, а не одним списком в
  конце, — «Вопросы и задания для самопроверки». Зачёт собран из них в порядке
  чтения, сквозной нумерацией: 25 вопросов первой главы, 50 второй, 22 третьей
  и 7 четвёртой.
- **В первых двух главах нет расчётов**, и тренажёров-расчётов у них тоже нет.
  Зато есть два порядка (что платится из наследства раньше и в каком порядке
  гасятся долги) и семнадцать разборов.
  Таблицы второй главы — это и есть разборы: у каждого наследника своя, и
  задание кладёт случай под ту долю, которую книга ему даёт. Доля супруга,
  отца, матери, дедушки, бабушек, потомков, братьев, сестёр, дядей — по разбору
  на каждого, потому что в этой науке путают не правило, а случай под правилом.
- **Вторая глава написана другой моделью и потом сверена по книге целиком.**
  Первое время её нельзя было проверить: оригинала глав 19–87 в репозитории не
  было, и в теме стояла оговорка. Теперь страницы прочитаны, и сверка дала вот
  что.

  **Зачёт совпал дословно.** Все 50 вопросов второй главы — 5 в разделе 2.1,
  5 в 2.2, 11 в 2.3, 12 в 2.4 и 17 в 2.5 — стоят в порядке книги и слово в
  слово. Содержание атомов тоже сошлось, вплоть до сноски 38 о том, что три
  мазхаба с Абу Юсуфом и аш-Шайбани исключают братьев только отцом, и до
  «Благословенного» и «Злополучного» братьев.

  **Восемь страниц указывали не туда, и они исправлены**: перечень мужчин
  (20 → 19) и женщин (21 → 20), обе доли сразу (23 → 22), три случая матери и
  «Умарские примеры» (30 → 29), довод о дедушке (34 → 33), случаи родной сестры
  и её зависимый та‘сиб (68 → 67). Во всех восьми на прежней странице искомого
  не было вовсе — только хвост списка или соседний пример.

  **Две оговорки дописаны, а не скрыты.** На с. 47 книга набирает номер аята о
  дочери как 4:14, хотя тот же аят приводит как 4:11 на с. 43 и с. 50, — атом
  держит верный номер и называет опечатку. У аль-Мудмиры страница 42 указывает
  на пример с числами, а сама она описана на с. 37–38; атом теперь говорит и
  это.

  Id атомов при этом не менялись, поэтому ни одна карточка в расписании
  ученика не сдвинулась: правились только страница и примечание.
- **Третья глава — арифметика, и спрашивается она арифметикой.** Книга сама
  ставит расчётные задачи («распределите 400 000 рублей между женой, двумя
  сыновьями и дочерью» — её вопросы 7–10), поэтому у главы свой вид тренажёра,
  `estate`: задание называет сумму, набор наследников и спрашивает про одного
  из них. Это не более лёгкий вопрос, чем у книги: чтобы назвать деньги одного,
  надо пройти весь путь — основа долей, доля каждого, нужна ли поправка,
  стоимость доли, — а проверяется одно число, и проверяется точно. Разбором на
  кучки это было бы не представить: кучек понадобилось бы семь только под
  основы долей, а расчёта не осталось бы вовсе.
- **Какая поправка нужна, в данных не записано — она следует из арифметики.**
  Долей вышло больше основы — это ‘ауль, и новой основой становится их сумма;
  меньше, и наследника конечной доли нет — это радд, и остаток возвращается,
  но **не супругу**: он берёт свою долю от всего наследства, и только остальное
  приращивается. Так это и устроено в книге, поэтому так же устроено и здесь:
  случай задаётся набором наследников, а не пометкой «тут ‘ауль».
- **Сумма в задании подбирается так, чтобы ответы вышли целыми рублями.**
  Генератор считает долю каждого точной дробью от наследства и берёт общий
  знаменатель: округления в учебном расчёте быть не должно, иначе ученик
  сверяет свой верный ответ с неверным.
- **Расчёт сверен с собственными примерами книги.** Все десять доведённых до
  рублей примеров третьей главы воспроизводятся точно — обычный раздел, оба
  примера ‘ауля, оба радда (с супругом и без) и «пример ослов», где родному
  брату по ханафитскому мнению не достаётся ничего. Это и лежит в
  `tests/topics.test.mjs`: не выдуманные числа, а те, что напечатаны в книге.
- **Четвёртая глава — спор, и разбирается она как спор.** Два вопроса: дедушка
  с братьями и сёстрами и родня материнского родства (заву аль-архам). Здесь
  почти нет правил, которые можно посчитать, зато есть позиции и доводы, и
  разборы сортируют именно их: кто держит какое мнение, каким доводом, какая
  школа. Третий разбор — способ раздела при дедушке: книга даёт по примеру на
  каждый из четырёх способов («как брат», «треть всего», «треть остатка», «одна
  шестая»), и они же стали кучками.
- **Заву аль-архам считаются тем же расчётным тренажёром.** Ничего нового он
  не потребовал: оба примера книги ложатся на него как есть — жена и дочь дяди
  (супруга остатка не получает) и две дочери с сыном родной сестры (два к
  одному). Это и есть проверка, что `estate` описывает раздел, а не один
  частный случай третьей главы.
- **Словарь книги взят не весь, и это решение.** Термины, которые тема уже
  спрашивает главами I–III — ‘ауль, радд, та‘сиб, хаджб, фард, дараджа, джиха,
  кувва, асль, сахм, — второй карточки не получают: две копии одного правила
  разойдутся на первой же правке, и это то же правило, по которому эталон
  зачёта собирается из атомов, а не пишется заново. Взято тринадцать статей,
  которых в теме не было: варис, муваррис, мирас, джахилия, джумхур, ‘идда,
  иджма, кыяс, каффара, кысас, муртад, назр и основатели четырёх мазхабов.
- **Приложения книги в тему не пошли.** Приложение № 1 — схема родственников
  рисунком, и пересказывать её словами значит делать другую вещь. Приложение
  № 2 — таблица недопущения, та же, что уже разобрана в третьей главе списками
  «кого не допускает кто»; вторая её копия ничего не добавила бы, кроме
  расхождения при первой правке.
- **Разбор по четырём кучкам — это мазхабы.** Разногласие здесь не в самом
  убийстве, а в его видах, поэтому у каждого мазхаба ровно один ответ, и в
  задание попадают все четыре сразу.
- **Вопрос 10 книги спрашивает «причины», заканчивая раздел об условиях.**
  Формулировка оставлена как напечатана, а эталон говорит, что в разделе три
  условия, и отсылает к вопросу 14, где книга спрашивает причины по-настоящему.
- **Там, где книга спорит сама с собой, тема помечает это знаком «?».** Четыре
  таких места, и все четыре теперь держат книжное. На с. 47 номер аята о дочери
  напечатан как 4:14, тогда как тот же аят книга приводит как 4:11 на с. 43 и
  с. 50, — карточка называет 4:14, как на её странице. На с. 83 пример даёт
  единоутробным брату и сестре вместе одну шестую, тогда как правило на с. 80 и
  аят 4:12 дают двоим треть, — ответ держит правило со с. 80. На с. 86 книга
  спрашивает о случаях наследования сыном родной сестры, которого сама в
  перечень наследников не внесла, — и вопрос зачёта стоит как напечатан.
  И страница аль-Мудмиры (42) указывает на пример с числами, а сама она описана
  на с. 37–38. Раньше здесь стояли примирения и отсылки к учителю; теперь
  карточка сообщает расхождение и оставляет решение автору темы.

### Очищение по аль-Кудури — что в этой теме своего

- **Это третья книга темы** и первая, разобранная не мной: раздел очищения из
  «Комментариев к „Мухтасар аль-Кудури“» — толкование Мухаммада Ашика Иляхи
  аль-Барни, перевод Р. Тагирова и Р. Нургалеева, Казань: РИИ, 2016, с. 40–90.
  Прислана готовым файлом и подключена после проверки — тем самым способом, ради
  которого написан [docs/topic-authoring.md](./docs/topic-authoring.md).
- **Книга прочитана, и тема по ней сверена.** Сначала её не было, и сверять
  страницы было нечем; потом PDF лёг в ветку `book-source` рядом с «Шифахией»,
  и сверка дала вот что.

  **Зачёт совпал дословно.** Книга закрывает раздел своим списком «Контрольные
  вопросы к разделу» на с. 84–90 — ровно 101 вопрос, и все 101 стоят в теме в
  её порядке и её словами. Сверка машинная, в `tests/topics.test.mjs` записан
  её итог.

  **Сорок страниц указывали на страницу раньше нужной**, и они исправлены. Ошибка
  системная: книга печатает матн аль-Кудури в скобках, а комментарий разворачивает
  его дальше, и там, где ответ давал не матн, а комментарий, страница отставала
  на одну — части тела в вуду (40 → 41), труднодоступные места в гусле (45 → 46),
  большой водоём и смерть в воде (52 → 53), вёдра из колодца (54 → 55), вода после
  кошки (57 → 58), способ тайаммума (60 → 61), поиск воды путником (64 → 65),
  замена омовения ног (66 → 67), обычные носки и повязка (69 → 70), нормы
  истихады (74 → 75), весь нифас (76 → 77). Девять занятий получили свои
  настоящие диапазоны, а вопрос о том, что нарушает тайаммум, переехал в занятие
  о самом тайаммуме — он на с. 61, а не на 62.

  Id единиц при этом не менялись, поэтому ни одна карточка в расписании ученика
  не сдвинулась: правились только страницы.
- **Зачёт — весь контрольный список книги**, и ни один вопрос не опирается на
  `extra`: на каждый отвечают атомы самой темы. Формулировки книжные до буквы —
  вопрос 15 напечатан как «Это порядок совершения полного омовения…», и так он в
  теме и стоит, хотя сам текст на с. 46 говорит «Этот порядок».
- **Расчётов здесь нет.** Таблицы раздела — это не арифметика, а разбор:
  сколько вычерпывать из колодца по размеру павшего животного, чья остаточная
  вода чиста, порицаема или сомнительна, что относится к тяжёлой и лёгкой
  нечистоте. Плюс три порядка: фарды вуду по аяту, суннатский гусль и тайаммум.
- **От матна не отходят, а несходящееся помечают.** Два места. Сноска на с. 81
  зовёт чистым помёт птиц, чьё мясо едят, — речь о голубе и мелких птицах, — а
  список тяжёлой нечистоты на той же странице называет помёт курицы, утки и
  гуся. И пояснение на с. 73 набрано с обратным смыслом против основного текста
  на с. 71: «является менструальной кровью, даже если она будет чисто белого
  цвета». Обе карточки говорят книжное, а знак «?» рядом называет расхождение.

### Намаз, закят, пост и хадж по аль-Кудури — что в этих темах своего

- **Четыре раздела одной книги подряд**, той же, что дала тему «Книга
  очищения»: намаз (с. 91–227), закят (с. 229–262), пост (с. 263–281) и хадж
  (с. 282–359). Написаны не мной и присланы готовыми файлами; здесь они сверены
  по книге и подключены. Вместе с очищением это вся первая часть издания.
- **Зачёты совпали с книгой дословно**: 274 вопроса намаза, 91 закята, 47 поста
  и 144 хаджа — ровно столько, сколько книга печатает в своих списках
  «Контрольные вопросы к разделу» (с. 209–227, 257–262, 278–281 и 349–359), в её
  порядке и её словами. Сверка машинная, по тексту самой книги.
- **Книга дважды печатает один и тот же вопрос**, и каждый раз это сохранено: у
  намаза № 11 и № 12 (с. 209), № 271 и № 272 (с. 227), у поста № 45 и № 46
  (с. 280), у хаджа № 56 и № 57 (с. 352), № 87 и № 88 (с. 355). Убрать дубль
  значило бы сбить сквозную нумерацию, по которой ученик сверяется с книгой,
  поэтому оба номера стоят на месте со знаком «?».
- **А в хадже книга ещё и разорвала фразу нумерацией.** Вопрос № 131 кончается
  на «забоя жертвен», а № 132 — это «ного животного?»: слово разрезано границей
  страниц 358 и 359, и вторая половина получила свой номер. Обе позиции стоят
  как напечатаны, со знаком «?».
- **Сорок страниц в теме намаза указывали не туда**, и они исправлены по книге —
  та же причина, что и в теме очищения: матн идёт в скобках, комментарий
  разворачивает его дальше, и страница отставала на одну-три. Две единицы
  указывали на с. 110, где нет ни строчки по-русски: вся страница арабская, и
  ответ стоит в переводе матна на с. 111. Id единиц не менялись, поэтому ничего
  в расписании ученика не сдвинулось.
- **Хадж пришёл со своими страницами в порядке** — ни одной правки не
  потребовалось, и это же говорит, что сорок сдвигов в намазе были свойством
  того раздела, а не общей манерой автора тем.
- **Зачёт намаза был связан с фактами по месту, а не по смыслу**, и это
  пересверено целиком. Связи расставлялись позиционно: вопрос N вёл к N-му
  факту занятия, — и на каждом «Разъясните…», после которого нумерация
  сдвигалась, разъезжались дальше. «Что такое заря заката?» вело ко второму
  рассвету, запретные времена отставали на три, саждат ат-тилява — на один.
  Все 274 вопроса сверены по одному со страницами их ответов; связь поменялась
  у 185. **Это важно не для вида:** `ExamQuestionCard` собирает эталон и двигает
  расписание именно по указанным фактам, поэтому неверная связь роняла в коробку
  не тот факт, о котором спрашивали. Шесть вопросов книга отвечает правилом,
  которого у темы нет карточкой, — их ответ сказан в `extra`, и их список
  закреплён тестом. У хаджа так же оказался один вопрос (№ 102, двое в ихраме
  срубили дерево), связанный с совместной охотой двоих вне ихрама.
- **Тезисы занятий написаны заново.** В четырёх темах по аль-Кудури все 109
  занятий несли одни и те же три общие строки («проверяйте ответ по указанной
  странице»), а `brief` — это карта именно этих страниц: что держать в голове,
  читая их. Теперь у каждого занятия свои, и тест не пускает повторяющуюся
  строку обратно.
- **Расхождения самой книги помечены знаком «?», а не исправлены.** Русский
  текст на с. 256 печатает размер садакат аль-фитр как «са‘ пшеницы или половина
  са‘а фиников, изюма или ячменя», тогда как арабский матн на с. 254 говорит
  обратное — половина са‘а пшеницы и целый са‘ фиников, изюма или ячменя;
  карточка держит напечатанное по-русски и называет расхождение. В теме поста
  примечание на с. 265 ставит изюм рядом с половиной са‘а, а основной текст той
  же страницы связывает целый са‘ с финиками и ячменём. В хадже таких мест ещё
  два: на с. 320 искупление по уважительной причине названо «трём беднякам»,
  хотя тут же три са‘а пшеницы делятся по половине са‘а — то есть на шестерых; а
  на с. 336 микаты жителя Харама дважды напечатаны «для совершения хаджа», хотя
  по изложенной там же системе второй случай — умра. Карточки держат
  напечатанное, «?» называет расхождение.
- **Тренажёры — таблицы закята и порядки обрядов.** У закята считаются ступени
  по верблюдам и мелкому скоту, а кучками разбираются коровы, орошение,
  получатели, родственники и время садакат аль-фитр — те же виды, что в теме
  закята по «Фикх аль-ибада», только числа здесь книжные. У намаза четыре
  порядка (ракаат, праздничный намаз, омовение умершего, погребальный намаз) и
  два разбора: фард против ваджиба и сунны и допустимость следования за имамом.
  У поста — последовательность искупления и три разбора.

### «Стилистика арабского языка» — что в этих темах своего

Четыре темы по одной книге (М.: «Сад», 2008): возникновение науки и три её
направления. Написаны не мной и присланы готовыми файлами; здесь сверены по
книге и подключены.

- **Все три главы покрыты целиком.** Глава I — введение и §§ 1–17 (с. 12–75),
  глава II — введение и §§ 1–16 (с. 76–158), глава III — обе её части, §§ 1–9,
  полезное послесловие и заключение (с. 159–189). Список литературы и
  оглавление в темы не брали.
- **Глава I дописана §§ 5–17, и это не стоило ученику ни одной карточки.**
  Сначала тема взяла только введение и §§ 1–4 (с. 12–30) — фасаху, балагу и три
  стиля речи; собственно приёмы بيان остались за бортом. Дописаны они были
  ровно тем способом, который здесь и обещан: тринадцать занятий легли в конец
  `steps`, тридцать девять упражнений — в конец зачёта, а все семь прежних
  занятий, 50 фактов, 4 тренажёра и 12 упражнений остались на своих местах с
  теми же id и тем же содержимым. Проверено сверкой старого файла с новым до
  установки, как при заливках глав наследственного права.
- **Зачёт — упражнения самой книги**, собранные в порядке чтения: 51, 48 и 25.
  У раздела о возникновении стилистики книга упражнений не даёт, и зачёта у него
  нет вовсе — по тому же правилу, по которому его нет у «Ясных разъяснений».
- **Семь мест помечены знаком «?», и все семь сверены по книге.** Четыре —
  опечатки издания: `الْكَشَّافُ` передан по-русски как «Лампа» (с. 10), «Выделите
  из низ цитаты» (с. 165), «Кто ропчет на судьбу» (с. 176) и слово `شِشْمًا`,
  данное без перевода и нигде не объяснённое (с. 16). Остальные три — места, где
  книга спорит сама с собой, и во всех трёх карточка держит согласованное
  чтение, а не печатное, и говорит об этом вслух:
  - на с. 89–90 книга **четырежды** называет адресатом аята «Худ», 37 пророка
    Мусу, тогда как «они будут утоплены» обращено к Нуху;
  - на с. 55 заголовок § 13 гласит `الإِسْتِعَارَةُ الأَصْلِيَّةُ وَالتَّبَعِيَّةُ`, а в двух
    строках определений арабские названия переставлены: основная подписана
    `التبعية`, производная — `الأصلية`. Карточки идут за заголовком и за самими
    определениями;
  - на с. 72 перечень видов намёка верен (`الكناية عن الصفة` — намёк на признак),
    но следующая строка называет разбор первого вида по-русски «намёк на связь
    признака с носителем», хотя арабский термин там `الصفة` и определение
    говорит о качестве.

### Как добавить тему

Импортёра здесь нет и не будет: разбор прозы на вопросы — работа суждения, а не
разметки. Тема пишется руками в `content/topics/<slug>.ts` и добавляется в
`TOPICS` в `content/topics/catalog.ts`; сводка (число занятий, фактов,
тренажёров) считается по самой теме, вписывать её не надо.

Полная инструкция по разбору раздела — [docs/topic-authoring.md](./docs/topic-authoring.md):
типы, правила разбора, все шесть тренажёров с примерами, чек-лист перед сдачей,
скелет файла и правила сдачи работы. Документ самодостаточен — его можно отдать
целиком другой модели вместе с текстом раздела, вместе с готовым промптом из
раздела 11.

**Четыре его правила стоят того, чтобы знать их и здесь**, потому что каждое уже
стоило разбора, а тесты ловят не все:

- **запись многострочная** — однострочный объект упирается в предел контекстного
  вывода типов и роняет весь `steps` с `TS2322`, а `npm test` этого не видит;
- **вопрос зачёта связывается с атомами по смыслу, а не по месту** — позиционная
  расстановка дала 185 неверных связей из 274 в теме намаза, и расписание
  двигало не тот факт, о котором спрашивали;
- **`source.section` описывает то, что в файле** — не всю главу, если взята её
  часть;
- **новый раздел уже стоящей на полке книги ставится рядом со своими**:
  `TOPIC_BOOKS` группирует по непрерывному куску, и разрыв даёт книге два
  разделителя.

Порядок разбора текста, который себя оправдал:

1. Разбить раздел на занятия по подзаголовкам книги, 5–12 фактов на занятие,
   и выписать страницы.
2. Каждое утверждение книги превратить в вопрос с коротким ответом. Перечисления
   не разрывать — они `list`.
3. Там, где спутать есть что, дописать 2–3 неверных варианта: не выдумки, а
   соседнее правило той же книги.
4. Таблицы и проценты вынести в тренажёры.
5. Вопросы для повторения, если книга их даёт, взять зачётом как есть и связать
   каждый с атомами, из которых собирается эталон. Если книга спрашивает после
   каждого подраздела, а не в конце, — собрать их в порядке чтения и нумеровать
   сквозным счётом.
6. Тему, у которой прочитана не вся книга, писать на то, что есть: следующая
   глава допишется в конец `steps` и в конец зачёта, ничего не сдвинув.
7. Прогнать `npm test` (тест темы проверяет страницы, варианты, ссылки зачёта и
   ответы тренажёров).

## Источник контента — книга

Оригинал: **Ахмад Хади Максуди, «Учебник арабского языка ШИФАХИЯ»**,
составитель Н.И. Фаткуллин, Уфа 2011. 426 страниц.

Файл `sources/ШИФАХИЯ на русском полная версия.pdf` лежит **только в ветке
`book-source`** и в `.gitignore` — в `main` он не попадает. Достать его в
рабочее дерево:

```bash
git fetch origin book-source
git checkout origin/book-source -- sources/
git reset sources/     # чтобы не утащить PDF в коммит рабочей ветки
```

**В той же ветке лежат книги тем.** `sources/Комментарии_к_«Мухтасар_аль_Кудури».pdf` —
издание, по которому написаны темы очищения, намаза, закята и поста; текстовый
слой у него рабочий (`pdftotext -layout`), и номера страниц PDF совпадают с
печатными. Тема, написанная по книге, которой в репозитории нет, проверяется
только на устройство и на сам фикх — поэтому книгу сюда и кладут.

`sources/rusca-arap-dili-belagati.pdf` — И. Н. Хайбуллин, «Стилистика арабского
языка» (М.: «Сад», 2008, ISBN 978-5-902855-71-2), 197 страниц PDF. По ней
написаны темы баляги. Две её особенности стоят того, чтобы знать заранее:

- **Номер страницы PDF на два больше печатного.** Печатная с. 8 — это PDF 10.
  У «Кудури» они совпадают, и по привычке легко сверить не ту страницу.
- **Арабский из текстового слоя бит**, как в «Шифахии»: буквы расходятся
  пробелами, огласовки отрываются. Русский, наоборот, извлекается чисто.
  Рабочий режим тот же — русский из `pdftotext -layout`, арабский с картинки
  через `Read` с `pages`.

Книга делит себя на три главы, и их границы проверены: печатная с. 12 —
«Глава Первая. Наука разъяснения», с. 76 — «Глава Вторая. Наука о смыслах»,
с. 159 — «Глава Третья. Наука красноречия», текст кончается на с. 189.

**В `main` книги не живут.** Один раз они туда попали (PR № 70) и были убраны:
репозиторий публичный, а `book-source` для того и заведена. Ветку не удаляют
при мерже — если она пропала, её восстанавливают из истории, а не заводят
заново.

### Как читать книгу (важно)

**Арабский текст из PDF не извлекается.** Шрифт с битой кодировкой: и `pypdf`,
и `pdftotext` выдают на арабском мусор с потерянными и переставленными буквами
(`الدَّرْسُ الأَوَّلُ` → `اليَّ لْ جُ الْل`). Полагаться на извлечённый арабский нельзя ни при
каких обстоятельствах — это прямой путь к ошибкам в учебном материале.

Рабочий способ — **читать страницы визуально**, инструментом `Read` с
параметром `pages` (до 20 страниц за раз). Требуется `poppler-utils`
(`apt-get install -y poppler-utils`), в свежем контейнере его нет. Огласовки
на рендере видны отчётливо.

Русская часть, наоборот, извлекается корректно:
`pdftotext -layout book.pdf book.txt` даёт русские подстрочные переводы с
сохранением колонок. Практичный режим работы — арабский с картинки, русские
глоссы из текстового слоя, сверяя друг с другом.

### Карта книги (номера страниц PDF)

| Раздел | Страницы |
|---|---|
| Титул, введение | 1–3 |
| **Часть I** (уроки 1–50) | 4–135 |
| **Часть II** (уроки 51–100) | 136–297 |
| Грамматика | 298–385 |
| Словарь | 386–426 |

Опорные точки: урок 1 — с. 5, урок 20 — с. 44, урок 30 — с. 75,

Плотность неравномерная: в начале по 2 урока на страницу, дальше 3–6 страниц

дальше заголовки только арабские (`الدَّرْسُ السَّابِعُ وَالتِّسْعُونَ`), так что искать урок
по номеру текстовым поиском бесполезно — нужно листать визуально от опорной точки.

### Структура урока в книге

Заголовок → тематические блоки новых слов с русским подстрочником →
«Переведите предложения на русский язык» (арабские фразы) →
«Переведите предложения на арабский язык» (русские фразы).

Отображение на нашу модель: блоки слов → `decks[]` (заголовок блока в
`deck.title`), фразы из обоих упражнений → `questions[]`. Последним вопросом
урока по нашей конвенции идёт задание «найдите и исправьте ошибку» — его в
книге нет, он составляется самостоятельно на материале урока.

**Последние пять уроков устроены иначе.** Уроки 96–100 (с. 283–297) — не
словарь с упражнениями, а сплошное чтение: 96 — поток коротких предложений,
97 и 98 — «المَقَالَاتُ العَرَبِيَّةُ», арабские изречения, 99 и 100 —
«الحِكَايَاتُ العَجِيبَةُ», короткие рассказы. Отсюда два следствия, о которых
надо знать заранее:

- **Русского подстрочника там нет вовсе.** На пятнадцати страницах по-русски
  напечатаны три сноски — «Судный день», «воскрешение», «будь хорошим», — и
  больше ничего. Перевод карточек этих уроков наш, а не книжный; сверять его
  не с чем, кроме самого арабского.
- **Огласовка к концу книги слабеет.** Уроки 96–98 огласованы полностью,
  в рассказах 99 и 100 харакаты стоят частью. Курсу нужна полная огласовка,
  поэтому в этих двух уроках она проставлена нами.

## Ключевые механики (`app/page.tsx`)

- **`expandLessonQuestions`** (в `content/questions.ts`) добивает список вопросов
  до `words.length * 2` автосгенерированными парами (ар→ру и ру→ар) для каждого
  слова. Авторский последний вопрос («найдите ошибку») всегда остаётся последним.
- **Задание может недобрать вариантов, и это решается пройденным.**
  `buildOptions` выбрасывает кандидата, у которого есть общее значение с
  ответом, — иначе у вопроса оказалось бы два правильных ответа. Там, где
  толкования длинные, общим оказывается служебное слово: «предмет, которому
  приписывается превосходство» и «предмет, с которым производится сравнение»
  делят «предмет», и в уроке из трёх слов оставалось два варианта вместо трёх.
  Поэтому добор из пройденного включается **по факту нехватки**, а не по числу
  слов в уроке: `textCourseNeedsMetWords` строит задания из своих слов и
  смотрит, вышло ли три варианта. Проверяется тестами четвёртой и пятой частей.
- **Дистракторы** подбирает `buildOptions` там же. Кандидаты ранжируются по
  «спутываемости» (общий префикс/суффикс после снятия огласовок, близость длины)
  с бонусом за принадлежность к той же колоде; из лучшей половины (не более 6)
  два варианта выбираются детерминированным перемешиванием с сидом от ответа.
  Сид обязателен: генерация идёт на модульном уровне и должна совпадать на
  сервере и клиенте. Кандидат, у которого есть общее значение с ответом
  (`«высокий / длинный»` против `«длинный»`), отбрасывается — иначе у вопроса
  оказалось бы два правильных ответа.
- **Экраны** — одно состояние `view`: `home | learn | practice | review | result`.
  Роутинга нет, всё на одном URL.
- **Длинные уроки идут в две части.** Порог — `PART_THRESHOLD = 150` заданий в
  `content/lesson-parts.ts`; сейчас делятся 10 уроков (33, 44–49, 53, 54, 59).
  Карточки режутся по границе колоды, ближайшей к середине (колода — одна тема,
  разрывать её нельзя), задания — ровно пополам, поэтому завершающее «найдите
  ошибку» остаётся во второй части. Счёт и список ошибок копятся через обе
  части, поэтому итог — за весь урок. Когда первая часть закончена, сессия
  сразу сохраняется на начало второй: уйти с экрана результата можно, не
  потеряв пройденное. `finishLesson` вызывается только на последней части — до
  этого урок не считается пройденным.
- **Загрузка контента ленивая.** Главная рендерится из `content/manifest.ts`
  (сгенерированные метаданные, ~39 КБ), сам урок приезжает отдельным чанком
  при открытии — `openLessonsById` в `app/page.tsx`. На старте подгружаются
  только урок незавершённой сессии и уроки, по которым есть карточки
  повторения. `reviewCatalog` строится из загруженных уроков, а не из всего
  курса. Поэтому `lesson` может быть `undefined` — режимы `learn`/`practice`/
  `result` закрыты проверкой, пока урок не приехал.
- **Интервальное повторение**: `REVIEW_INTERVALS = [0, 1, 3, 7, 14, 30]` дней,
  коробки Лейтнера. Каждое слово даёт две карточки (`ar-ru` и `ru-ar`), id вида
  `lesson-{id}-deck-{i}-word-{j}-{direction}`. Слово считается выученным, когда
  **обе** карточки в максимальной коробке.
- **Хранилище — `localStorage`**, читается через `useSyncExternalStore`
  в `app/progress-store.ts`: сервер отдаёт пустой снимок, гидрация с ним
  совпадает, сохранённые значения приезжают тем же механизмом, что React
  использует для любого внешнего источника. Копировать localStorage в
  `useState` на маунте не нужно и нельзя — правило `set-state-in-effect`
  на это ругается. Ключи:
  `shifahiya-lesson-{id}` (счёт), `shifahiya-lesson-total-{id}` (из скольких
  заданий он набран), `shifahiya-grammar-{id}` (счёт грамматики),
  `shifahiya-session-{id}` и
  `shifahiya-active-session` (незавершённая сессия), `shifahiya-card-progress-v1`,
  `shifahiya-reading-v1` (расписание чтения), `shifahiya-exams-v1` (результаты
  экзаменов), `shifahiya-exam-session` (незаконченная работа),
  `shifahiya-p2-lesson-{id}` и `shifahiya-p2-session-{id}` (вторая часть),
  `shifahiya-p3-lesson-{id}` и `shifahiya-p3-session-{id}` (третья часть),
  `shifahiya-p4-lesson-{id}` и `shifahiya-p4-session-{id}` (четвёртая часть),
  `shifahiya-p5-lesson-{id}` и `shifahiya-p5-session-{id}` (пятая часть),
  `shifahiya-p6-lesson-{id}` и `shifahiya-p6-session-{id}` (шестая часть),
  `shifahiya-p7-lesson-{id}` и `shifahiya-p7-session-{id}` (седьмая часть),
  `shifahiya-p8-lesson-{id}` и `shifahiya-p8-session-{id}` (восьмая часть),
  `shifahiya-p9-lesson-{id}` и `shifahiya-p9-session-{id}` (девятая часть),
  `shifahiya-p10-lesson-{id}` и `shifahiya-p10-session-{id}` (десятая часть),
  `shifahiya-learning-stats-v1`. Отдельно от курса — темы наизусть:
  `shifahiya-topic-cards-v1` (расписание по каждому вопросу темы),
  `shifahiya-topic-steps-v1` (разобранные занятия),
  `shifahiya-topic-exams-v1` (зачёты по темам). Плюс ручной экспорт/импорт JSON
  (`format: "shifahiya-progress", version: 1`) — при изменении формата поднимать
  `version` и суффикс `-vN` в ключах.
- **Синхронизация между устройствами — Supabase, необязательная.**
  `app/supabase-config.ts` пустой по умолчанию; пока он пустой, `startSync()`
  выходит сразу, панель входа не рендерится и наружу не уходит ничего.
  Заполнены — на главной появляется кнопка входа через Google. Провайдер, а не
  ссылка на почту: встроенная почта Supabase ограничена парой писем в час.
  - `localStorage` остаётся источником истины, сервер — копия. Офлайн-режим
    ломать нельзя: это условие, при котором синхронизацию вообще добавляли.
  - Вход **не перезаписывает** местный прогресс. `app/merge-progress.ts` —
    чистый модуль слияния: счёт — максимум, карточка — та, где позже
    `lastReviewed` (дальше по `box`, затем по числу ответов), сессия — свежая
    по `updatedAt`, даты и фразы — объединение. Слияние коммутативно, это
    проверяется тестом; `masteredPhrases` и `activeDates` для этого сортируются.
  - Импортирует из `progress-store` **только типы** (`import type`) — иначе
    тест не сможет загрузить модуль под `--experimental-strip-types`.
  - `app/sync.ts` держит состояние входа во втором внешнем сторе
    (`syncStore`) и грузит `@supabase/supabase-js` динамическим импортом:
    пакет весит вдвое больше всего курса и в стартовый чанк попадать не должен.
    Проверять после правок: чанка `dist-*.js` не должно быть в разметке
    `.static-site/index.html`.
  - Пуш дебаунсится (`SETTLE_MS`) с потолком ожидания (`MAX_WAIT_MS`) и
    досылается на `pagehide`/`visibilitychange`: полный прогресс — около
    мегабайта JSON, отправлять его на каждый ответ нельзя.
  - Схема БД и политики RLS — `supabase/schema.sql`, применяется вручную через
    SQL Editor. Ключ `anon` публичный по замыслу, доступ ограничивают политики.
- **Урок можно наращивать, пройденное при этом не отнимается.** Три правила,
  без которых наращивание крадёт чужой прогресс:
  - **Колоды только дописываются в конец.** Адрес карточки повторения —
    `lesson-{id}-deck-{i}-word-{j}-{dir}`; вставка слова в середину молча
    переназначила бы коробки Лейтнера соседям.
  - **Счёт хранится вместе со своим знаменателем** (`shifahiya-lesson-total-{id}`).
    `isLessonComplete` смотрит только на наличие счёта, поэтому урок остаётся
    пройденным и следующий не перезакрывается, — но карточка печатала счёт
    поверх сегодняшнего числа заданий, и «26/56» превращалось в «26/96». У
    записей, сделанных до этого, знаменателя нет, и тогда показывается просто
    «✓ 26 верных»: выдумывать его нельзя. При слиянии устройств знаменатель
    едет за тем счётом, который победил, а не берётся больший.
  - **Часть сессии пересчитывается при возобновлении.** `partIndexFor` в
    `content/lesson-parts.ts` определяет часть по сохранённой позиции, а не по
    сохранённому номеру части: урок, перешагнувший порог, делится надвое, и
    брошенная в нём сессия иначе возобновилась бы не в своей половине.

  Проверяется `tests/growing-lesson.test.mjs`.
- **Озвучка** — Web Speech API, `speak()` с `lang = "ar-SA"`. Поле `Word.audio`
  объявлено, но не заполнено и нигде не читается — задел на реальные аудиофайлы.

## Тесты

`npm test` собирает проект и прогоняет `tests/*.test.mjs` под
`--experimental-strip-types` — благодаря этому тесты импортируют `.ts`-модули
напрямую (с обязательным расширением в пути). `content/lessons.ts` так
импортировать нельзя: `import.meta.glob` разрешает только сборщик, — поэтому
в тестах уроки грузятся чтением каталога.

`tests/questions.test.mjs` — настоящие поведенческие проверки генератора на всех
100 уроках: добивка до `words * 2`, уникальность вариантов, отсутствие второго
правильного ответа, разнообразие дистракторов и детерминированность. Новую
логику генерации проверять здесь.

`tests/rendered-html.test.mjs` делает две вещи: (1) импортирует собранный
`dist/server/index.js` и проверяет SSR-разметку главной, (2) читает исходники
как **текст** и проверяет их регулярками.

Второй тест хрупкий и растёт линейно с числом уроков (~100 `readFile` подряд).
При правках `app/page.tsx` он может упасть на регулярке, а не на реальной
поломке — это ожидаемо, регулярку в таком случае надо обновлять вместе с кодом.
Тест **не должен** мешать рефакторингу: если проверка привязана к формулировке
кода, а не к поведению, её правильно переписать на структурную или перенести
в `questions.test.mjs`.

`tests/part2.test.mjs` проверяет вторую часть — и с недавних пор её огласовку:
у книги «Кыраа рашида. Часть 2» конец шёл голым скелетом, а прогон был зелёный,
потому что вторая часть единственная не имела такой проверки. Планка та же, что
у третьей и четвёртой частей (85%); слабейший урок курса — 91%. Там же проверка,
что в уроки не просочился markdown-слеш.

`tests/part4.test.mjs` проверяет четвёртую часть по её собственным правилам, а
не по образцу третьей: урок без новых слов не задаёт вопросов и всё же несёт
текст; вопрос отдаёт три варианта даже там, где у урока одно слово, и ни один из
них не берётся из непройденного; кита́б идёт непрерывным куском, а баб не обязан;
заголовок внутри урока сохраняет пометку, и экран чтения ею пользуется.

`tests/part5.test.mjs` проверяет пятую часть по образцу четвёртой, но с двумя
поправками на грамматику: буква-метка списка («(أ) … (ب) … (ج)» — таких строк
три) огласовке не подлежит, и татвиль-разделитель не считается словом. Он же
поймал дефект генератора заданий, описанный ниже.

`tests/part6.test.mjs` проверяет шестую часть. Он же снял ложное срабатывание,
общее для всех четырёх текстовых частей: проверка «вариант, отличающийся от
ответа только огласовками, — второй правильный ответ» снимала огласовки со
всего, что содержит арабские буквы, а русское толкование может цитировать
арабскую частицу («соединение предложений союзом وَ» против «отказ от соединения
предложений союзом وَ» — противоположные значения). Теперь проверка смотрит
только на варианты без кириллицы.

`tests/part8.test.mjs` проверяет восьмую часть по образцу седьмой, плюс своё:
что бейт поэмы сохраняет пометку и что её знает экран чтения. Он же поймал
двенадцать строк оглавления, пришедших без огласовок.

`tests/part9.test.mjs` проверяет девятую часть по образцу восьмой, без проверки
стиха: бейтов эти книги не печатают.

`tests/part10.test.mjs` проверяет десятую часть по образцу шестой — каждый урок
приносит свои слова, — и вдобавок то, чего раньше не было: что двузначный
префикс карточки `p10-` не путается ни с одним однозначным, в обе стороны.

`tests/part7.test.mjs` проверяет седьмую часть — по образцу шестой, с поправкой
на то, что здесь есть урок без новых слов (23-й), а там его не было. Он же
поймал разделитель, считавший диапазон раздела по обеим книгам сразу.

`tests/topics.test.mjs` проверяет часть «темы наизусть» по её собственным
правилам, и проверки материала идут по **всем** темам: страница каждого вопроса
лежит внутри раздела книги, адреса карточек не повторяются, у списка есть
пункты, а у написанных руками вариантов нет второго правильного ответа; зачёт
нумерован подряд и ссылается только на существующие атомы. Дальше — поведение расписания (коробки растут,
последняя держит, забытое возвращается сегодня же и считается потерей,
«частично» опускает ровно на одну коробку) и ответы тренажёров, сверенные с
вопросами 11–13 и 19 самой книги: 26 верблюдов, 25 коров (нисаба нет), 600 овец.
Разборы проверяются на то, что каждая кучка непуста и попадает в задание, а
порядок — на то, что окно берётся подряд и никогда не приходит уже решённым.
Ответы разборов паломничества сверены с вопросами 4 и 39–48 книги, разбор по
мазхабам — на то, что у каждого мазхаба ровно один ответ и все четыре попадают
в задание, а оба порядка наследственного права — на свою последовательность.
Расчёт наследства сверен с десятью примерами третьей главы, доведёнными в
книге до рублей: обычный раздел, оба примера ‘ауля, оба радда и «пример ослов».
Плюс проверка на всех сидах, что доля выходит целыми деньгами и разбор называет
основу долей.
Плюс два теста на решения: хранилище тем не трогает курсовых ключей, а
`app/page.tsx` знает про счётчик повторений и не знает про содержимое тем.

`tests/podcasts.test.mjs` проверяет привычку смотреть подкасты: разбор
длительностей и ссылок на каналы, фильтр окна, закрепление выпуска за датой и
его устойчивость к перезагрузке, «Другое» и «Посмотреть ещё», серию, календарь и
итоги. Плюс два теста, привязанных к решениям, а не к коду: `app/podcast-youtube.ts`
не должен ходить никуда, кроме `googleapis.com`, а `app/page.tsx` — знать про
хранилище подкастов. Там же SSR-проверка маршрута `/podcasts`.

**Модули подкастов импортируют друг друга с расширением `.ts`** — иначе Node под
`--experimental-strip-types` их не разрешит. Общий тип `PodcastWatch` лежит в
`app/podcast-catalog.ts`, а не в хранилище, чтобы не было цикла импортов.

### Прогон в браузере

`npm run smoke` — единственная проверка, которая смотрит на приложение глазами
ученика, а не читает его исходники. Она отдаёт `.static-site` своим сервером,
открывает страницу в Chromium, заполняет хранилище так, чтобы восьмая часть
открылась, и проходит её первый урок целиком: 41 карточка → 41 задание →
44 фрагмента чтения → сохранённый результат, и там же — что бейт поэмы набран
стихом, а не ещё одной строкой прозы. Потом открывает урок без новых слов и
убеждается, что он начинается сразу с чтения; следом проверяет гейты девятой и
десятой частей — закрыты, пока предыдущая не пройдена целиком, и открываются,
когда пройдена. Перед ней нужен `npm run build:static`.

Идёт именно восьмая часть, потому что экраны у текстовых частей общие: пройденная
одна проверяет заодно остальные, — а у этой вдобавок есть бейт, которого нет ни
в девятой, ни в десятой.

Прогон заканчивается второй частью — темами наизусть: занятие разбирается
целиком (выбор, свободное припоминание, список с отметками), открывается зачёт
(занятия для этого подкладываются в хранилище — проходить тридцать четыре ради
одного экрана незачем) и проверяется, что у помеченного вопроса виден знак «?»
и открывается замечание, затем в очередь подкладывается карточка тренажёра и проверяется, что из неё приходит расчёт по
овцам, из второй темы — порядок обрядов, а из третьей — раздел наследства,
и что оценка за каждое доходит до расписания. У расчёта наследства прогон
дополнительно читает разбор до оценки: он обязан назвать основу долей, то есть
показать путь, а не только итог. Проверено внесением дефекта: снятая из разбора
основа долей даёт «разбор расчёта не называет основу долей» и код выхода 1. Там же сверяется, что коробки повторения курса от этого не изменились.
Формы вопроса тут целиком клиентские, и сказать, доходит ли оценка до
расписания, может только браузер.

- **Зачем она есть.** Тесты проверяют данные и модули; они не видят, оживает ли
  страница. Трижды это была решающая разница: статическая сборка рендерилась, а
  React молча не гидрировался, и ни одна кнопка не работала; в первом релизе
  третьей части арабский показывал коранические аяты нечитаемыми глифами
  шрифта; а экран зачёта тем ронял React на первом же «Показать эталон» —
  `check` был объявлен в типе `ExamQuestionCard`, но не разобран из аргумента,
  и сборка оставляла свободный идентификатор. При зелёном `npm test` все три
  раза; последний ловил только `tsc`, который в прогон не входит, поэтому у
  зачёта теперь своя проверка в браузере.
- **Что валит прогон.** Ошибка в консоли или необработанное исключение, пустой
  экран чтения, нечитаемый глиф Presentation Forms (`﴿﴾ ﷺ` и прочие законные
  лигатуры исключены), несохранённый счёт урока, карточки, не попавшие в коробку
  повторения, а также урок без новых слов, открывшийся не на чтении. Проверено
  внесением дефекта дважды: подложенные в фрагмент глифы дают «нечитаемых глифов
  на экране: 3» и код выхода 1, а снятое условие «нет слов — сразу чтение»
  оставляет экран пустым и валит прогон по таймауту, тоже с кодом 1.
- **Проверяется то, что публикуется, и так, как публикуется.** Первая версия
  скрипта поднимала `vinext start`, то есть воркер-сборку из `dist/`, — а
  `deploy.yml` выкладывает `.static-site`. Дефект переписывания адресов в
  `scripts/build-static.mjs` такой прогон обходил стороной, хотя именно он
  однажды оставил страницу отрендеренной и мёртвой. Теперь сайт отдаётся своим
  сервером прямо из процесса — заодно исчез дочерний процесс, а с ним и порт,
  который тот держал.
- **Сайт отдаётся из подкаталога `/ash-shifahiya-app/`,** как на Pages, а не из
  корня. Это не мелочь: с корня неверный адрес `/assets/…` разрешается прекрасно,
  и проверка пропускает ровно ту поломку, ради которой заведена. Проверено —
  подменённый на `/assets/…` адрес входного чанка с корня проходит незамеченным,
  а из подкаталога даёт `404 на …/assets/index-*.js` и код 1.
- **Ответ 4xx считается провалом.** 404 на ассете — это успешный HTTP-ответ,
  и `requestfailed` его не видит; без отдельной проверки статуса симптомом
  оставался бы таймаут без объяснения причины.
- **Без Chromium проверка пропускается,** а не падает: она не входит в
  `npm test` и не включена в CI, поэтому мерж не зависит от того, есть ли
  браузер на раннере. Путь спрашивается у самого Playwright — он знает и
  стандартный кеш `~/.cache/ms-playwright`, и `PLAYWRIGHT_BROWSERS_PATH`, — но
  отвечает и тогда, когда браузера там нет, поэтому каждый кандидат проверяется
  на существование; дальше идут раскладки стора, системные каталоги и
  `SMOKE_CHROMIUM`.

**Тему, пришедшую сериализованной в одну строку, переписывают в обычный вид —
и не ради вида.** У «Науки красноречия» компактная однострочная запись объектов
упиралась в предел контекстного вывода типов: TypeScript переставал сужать
`kind` до `"fact" | "list"` и ронял весь `steps` с `TS2322`. Тесты при этом были
зелёными — ошибку видит только `tsc`, который в `npm test` не входит. Перезапись
с проверкой «разобранная тема — та же самая» лечит это целиком. Так же поступали
с четырьмя файлами по аль-Кудури.

## Известные проблемы (актуальный техдолг)

Крупного долга не осталось. Мелочи:

1. `worker/index.ts` ссылается на тип `Fetcher` из Cloudflare Workers, которого
   нет в `tsconfig` — единственная ошибка `npx tsc --noEmit`. На сборку не
   влияет, типы стираются.
2. Второй тест в `tests/rendered-html.test.mjs` проверяет исходники
   регулярками и растёт линейно с числом уроков.

## Принятые решения

- **Грамматика и тексты для чтения в этом виде не показываются.** Решение
  автора, а не отложенная работа: `GRAMMAR_ENABLED` и `READING_ENABLED` стоят
  в `false` и сами по себе не включаются. Не предлагайте «вычитать переводы и
  включить» — это уже рассмотрено и отклонено. Данные при этом **остаются в
  репозитории**: тексты, грамматические блоки и грамматические вопросы
  экзаменов сохранены на случай, если к материалу вернутся в другом виде,
  а прогресс по ним лежит в хранилище нетронутым. Курс это ничего не стоит —
  ни один из двух слоёв не влияет ни на счёт, ни на коробки Лейтнера, ни на
  открытие следующего урока.
- **Синхронизация — Supabase, а не D1.** Требование появилось («чтобы прогресс
  не терялся на разных устройствах»), и выбран Supabase: сайт остаётся
  статикой на GitHub Pages, а готовая авторизация избавляет от своей. Скаффолдинг D1 (`db/`, `drizzle/`, `drizzle.config.ts`,
  `examples/d1/`, пакеты `drizzle-orm` и `drizzle-kit`) был удалён раньше как
  мёртвый груз и не возвращается. SIWC-хелперы (`app/chatgpt-auth.ts`)
  оставлены, но задачу не решают: они серверные и требуют хостинга OpenAI Sites.
  Ключевое условие, при котором синхронизацию согласовали, — она идёт **поверх**
  локального состояния, а не вместо него.
- **Третья часть открывается второй, а не экзаменом.** У второй части ключ —
  итоговая работа первой; у третьей ключ — сама вторая, пройденная целиком.
  Причина в том, чем эти части отличаются: вторая учит читать рассказы, третья
  даёт научный текст, и промежуточной проверки между ними нет — есть сто пять
  уроков чтения, которые и делают трактат читаемым.
- **Задания третьей части спрашивают значение слова, а не форму в пропуске.**
  Словарь книги примеров не даёт, и выдумывать их курс не стал: контекст здесь
  — сам текст урока, который ученик читает третьим шагом целиком. Из текста ради
  задания ничего не вырезается.
- **Четвёртая часть открывается третьей и живёт на её коде.** Ключ тот же, что у
  третьей части, — предыдущий курс целиком, без работы между ними. А поскольку
  урок в обеих частях идёт одинаково, четвёртая не завела вторых типов, второго
  движка заданий и вторых экранов: форма урока стала `TextCourseLesson`, экраны
  общие, а различаются данные, гейт и адрес карточки. Копия всего этого под
  номером 4 расходилась бы с оригиналом при первой же правке.
- **Урок четвёртой части вправе не приносить слов.** Словарь накопительный
  против всех предыдущих курсов, и притворяться, что в каждом уроке есть новое,
  значило бы выдумывать слова. Такой урок — чтение, и на карточке так и
  написано.
- **Неверные варианты для короткого урока берутся из пройденного, а не из всего
  курса.** Вариант прочитывают прежде, чем отвергнуть; показать в нём значение,
  которого курс ещё не давал, — то же самое, что дать его мимоходом и не
  спросить.
- **Подкасты — отдельный маршрут, а не режим курса.** Просмотр подкаста ничего
  не открывает и не влияет ни на счёт урока, ни на коробки Лейтнера: это вторая
  привычка рядом с курсом, а не его часть. Условие, при котором её вообще
  добавляли, — «цель выполнена» и «сколько просмотрено» остаются разными
  величинами.
- **Список выпусков собирается заранее, а не на лету.** Сайт статический, ключ
  YouTube в общий доступ не выкладывается, поэтому каталог коммитится импортёром.
  Ключ ученика в настройках — дополнение для тех, кто хочет свежий список без
  пересборки, а не замена этому.
- **Грамматика как пятая часть — это не отмена выключателя.** `GRAMMAR_ENABLED`
  выключает авторские грамматические блоки внутри уроков первой части, и это
  решение в силе. Пятая часть — две отдельные книги, «Тайсир ас-сарф» и
  «Ан-Нахв аль-вадых», переведённые целиком и читаемые как книги третьей и
  четвёртой частей. Одно другому не противоречит.
- **Десятая часть — сорок хадисов, и это матн, а не наука о нём.** Восьмая
  часть учит взвешивать сообщение, девятая — выводить решение; десятая даёт
  сам текст, о котором обе говорили. Поэтому она идёт последней в чтении, а не
  первой по лёгкости.
- **Недоогласованную выгрузку возвращают переводчику, а не заливают, снизив
  планку.** «Арбаин» пришёл на 83,1%, и 37 уроков из 46 не проходили проверку.
  Планка заведена ровно затем, чтобы просадка не жила незамеченной при зелёном
  прогоне, — однажды так и случилось со второй частью. Возврат стоил одного
  файла с пометками и вернулся стопроцентной огласовкой при неизменном скелете.
- **Девятая часть — усуль аль-фикх, и он идёт последним.** Не по старшинству:
  усуль спрашивает, откуда берётся решение, и рассуждает сразу обо всём, что
  ученик прочёл, — о словах аята, о цепочке сообщения, о кыясе. Матн идёт перед
  комментарием, как и в восьмой части поэма перед трактатом.
- **Прогон в браузере остался на восьмой части, а не переехал на девятую.**
  Правило «идёт самая новая» держалось на покрытии, а не на новизне: экраны у
  текстовых частей общие, и пройденная новая проверяет заодно старую. Здесь
  восьмая покрывает ровно то же и вдобавок бейт, которого в девятой нет, —
  переезд был бы потерей. Гейт девятой части прогон при этом проверяет
  отдельно: вкладка закрыта, пока восьмая не пройдена целиком, и открывается,
  когда пройдена.
- **Восьмая часть — хадисоведение, и оно идёт после логики.** Мусталах
  взвешивает не фразу и не довод, а цепочку, по которой сообщение дошло, — и
  этим занимаются, когда и фраза, и довод уже читаются. Внутри части поэма с
  комментарием идёт перед трактатом: так же устроены и сами выгрузки, словарь
  второй книги вычтен относительно первой.
- **Оглавление баба ученику не читается.** Двенадцать строк «Аль-Мадхаля»
  перечисляют фаслы, которые книга тут же открывает настоящими заголовками.
  Пропущены они поимённо и с проверкой — не по виду строки, иначе правило
  выкинуло бы и живой текст, — и огласованная версия этих строк остановит
  импорт, а не пройдёт молча.
- **Седьмая часть — логика, и она идёт после языковых наук.** Мантик взвешивает
  не фразу, а довод: этому учатся, когда доводы уже читаются. Приложение «Об
  авторе» из выгрузки в курс не берётся — это не урок книги.
- **Шестая часть — риторика, и она идёт после грамматики.** Это цепочка,
  которой открывается каждая часть, и классический порядок разом: балага
  взвешивает фразу, которую сарф и нахв уже сделали правильной.
- **Курс пятой части идёт последним, а не первым.** Соблазн поставить
  грамматику в начало есть, но она здесь не учит языку с нуля: она называет то,
  что ученик уже читает. Гейт — четвёртая часть целиком, как у всей цепочки;
  открыть раньше — это одна строка в `isPart5Open` и её тест.
- **Буква ё в третьей части остаётся как пришла.** Курс её не выравнивает ни в
  ту, ни в другую сторону: восстанавливать — ручной разбор каждого случая,
  снимать — терять «всё» против «все». На чтение это не влияет, и предлагать
  такую работу заново не нужно.
- **Темы наизусть — отдельная часть, а не восьмой курс.** Курс ведёт по книге
  «Шифахия» и книгам, которые за ней идут; тема — это чужая книга, которую
  ученик читает сам, и ей нужны не карточки со словами, а вопросы на понимание.
  Поэтому свой маршрут, своё хранилище, свои коробки и своё расписание, а с
  курсом их связывает только счётчик на главной.
- **Текст темы в приложение не переносится.** Ученик читает свою книгу; задача
  приложения — заставить вспомнить прочитанное и вернуть его вовремя. Отсюда
  страницы у каждого занятия и у каждого вопроса: сверяться надо с оригиналом,
  а не с нашим пересказом.
- **Оценка ставится учеником, а список — по пунктам.** Проза не проверяется
  сравнением строк, и притворяться, что проверяется, значит врать обеим
  сторонам. Зато перечисление проверяется честно: отмечается то, что названо,
  и оценка считается из этого.
- **Таблицы спрашиваются расчётом, а не узнаванием.** «Сколько с 26 верблюдов» —
  вопрос самой книги; число в задании каждый раз другое, поэтому запомнить
  ответ нельзя.
- **Расчётная глава получила свой вид тренажёра, а не была согнута в разбор.**
  Третья глава наследственного права — это арифметика, и книга сама ставит
  задачи на раздел суммы. Кучки тут не годятся по существу: под одни только
  основы долей их нужно семь, а считать ученику не пришлось бы вовсе. Поэтому
  добавлен шестой вид, `estate`. Экранам он не стоил ничего — ответ вводится
  числом, а эта форма уже была у закята; своё у него только генератор, и тот
  сверен с примерами самой книги.
- **Импортёра тем не будет.** Разбор прозы на вопросы — работа суждения:
  что здесь факт, что перечисление, где ученик спутает одно с другим. Скрипт
  этого не решает, а видимость решения хуже её отсутствия.

- Дописывать уроки 96–100 сейчас не требуется; книга-источник уже в репозитории
  (см. раздел «Источник контента»).
