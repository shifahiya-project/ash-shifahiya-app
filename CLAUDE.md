# Аш-Шифахия — интерактивный курс арабского языка

Учебное веб-приложение на русском языке по книге «Аш-Шифахия». Пользователь
проходит уроки: карточки со словами → тест с вариантами ответа → результат,
плюс отдельный режим ежедневного повторения по системе Лейтнера.

Интерфейс, контент и коммуникация с пользователем — на русском. Код,
идентификаторы, коммиты и комментарии в коде — на английском.

## Стек и платформа

- **Next.js 16 App Router** поверх [**vinext**](https://github.com/cloudflare/vinext) —
  рантайм App Router для Cloudflare Workers. Сборка/дев идут через `vinext`,
  а не через `next`. `wrangler.jsonc` не используется: локальные биндинги
  описаны прямо в `vite.config.ts`.
- **React 19**, **Vite 8**, **Tailwind 4** (подключён, но вёрстка почти целиком
  на своём CSS в `app/globals.css`).
- Хостинг — платформа OpenAI Sites. `.openai/hosting.json` объявляет
  опциональные биндинги D1/R2 (сейчас оба `null`); ни один не используется.
  Публикуется же собранная статика на GitHub Pages (см. «Публикация»).
- **Supabase** — единственная внешняя зависимость приложения, и та
  необязательная: только вход и синхронизация прогресса между устройствами.
- Node.js `>= 22.13.0`.

## Команды

```bash
npm run dev       # локальная разработка (vinext dev)
npm run build     # сборка в dist/ (vinext build)
npm run build:static  # статическая копия сайта в .static-site/
npm test          # build + node --test tests/*.test.mjs
npm run lint      # eslint
npm run content:manifest  # пересобрать content/manifest.ts после правки урока
```

`npm test` включает в себя `npm run build` — отдельно собирать не нужно.

## Публикация

Приложение целиком рендерится в браузере и держит состояние в `localStorage`,
поэтому курс работает и как набор статических файлов.
`scripts/build-static.mjs` рендерит главную через собранный Worker, переписывает
абсолютные адреса ассетов на относительные (иначе сайт ломается в подкаталоге —
для этого же в `vite.config.ts` есть `base: process.env.STATIC_BASE ?? "/"`) и
складывает всё в `.static-site/`. Рерайт нужен в двух местах: в разметке и в
экранированном payload гидрации — React пересобирает `<head>` на клиенте.

`.github/workflows/deploy.yml` повторяет сборку на каждый push в `main` и
выкладывает результат в ветку `gh-pages`; GitHub Pages отдаёт её по адресу
`https://shifahiya-project.github.io/ash-shifahiya-app/`. Ветка `gh-pages`
содержит только собранный сайт и переписывается целиком — руками её не править.

## Модель данных

`content/types.ts` — единственный источник истины:

```ts
type Word = { arabic: string; russian: string; note?: string; audio?: string };
type Question = {
  prompt: string; promptLang: "ar" | "ru";
  answer: string; options: string[]; explanation: string;
};
type GrammarRule = {
  kind: "nahw" | "sarf";
  title: string; term?: string; pattern?: string; explanation: string;
  examples: { arabic: string; russian: string; note?: string }[];
};
type GrammarBlock = {
  title: string; intro: string;
  rules: GrammarRule[]; questions: Question[];
};
type Lesson = {
  id: number; arabicTitle: string; title: string; description: string;
  tags: string[];
  decks: { title: string; words: Word[] }[];
  questions: Question[];
  grammar?: GrammarBlock;
};
```

Сейчас: 100 уроков, ~4540 словоформ, ~1075 авторских вопросов.

### Грамматика сейчас скрыта

`GRAMMAR_ENABLED = false` в `app/features.ts` — один выключатель на всё.
Курс сделал упор на лексику и чтение, поэтому грамматику временно не показываем.
**Ничего не удалено:** блоки лежат в файлах уроков, грамматические вопросы —
в экзаменах, а счёт `shifahiya-grammar-{id}` остаётся в хранилище и продолжает
синхронизироваться. Вернуть — поменять `false` на `true`, больше ничего.

Пока выключатель выключен:

- у урока нет грамматической части, он кончается своими словами;
- урок засчитывается по одному своему счёту — никого не держат на блоке,
  которого не видно;
- экзамены отдают только лексику: 80 вопросов вместо 100 (проходной 61) и
  114 вместо 150 (проходной 86);
- урок, брошенный внутри блока, считается пройденным: карточки и задания у
  ученика позади, и его счёт берётся из сохранённой сессии. Хранилище при этом
  не переписывается — включите грамматику обратно, и незаконченный блок
  вернётся ровно там, где был.

Правила ниже описывают блок таким, каким он включается. Функции доступа
(`isGrammarPassed`, `isLessonComplete`, `unlockedLessonIds`, `examReadiness`)
принимают выключатель последним аргументом, поэтому обе позиции проверяются
тестами: `tests/lesson-access.test.mjs` — включённую, `tests/features.test.mjs` —
выключенную.

### Грамматический блок (нахв и сарф)

Урок может нести разбор правил, по которым построены его формы. Блок —
**последняя часть урока**: сначала карточки и задания, потом теория и практика
к ней. `lessonParts` добавляет часть с `kind: "grammar"`; у неё нет колод, а
`questionStart/questionEnd` индексируют `grammar.questions`, а не `questions`.
Урок с одной частью получает часть 2, урок с двумя — часть 3.

- **Практика — обычный `Question`.** Движок заданий, счёт и сохранение сессии
  работают без изменений; новый экран нужен только для правила.
- **Блок обязателен, и его нужно сдать.** `isLessonComplete` в
  `app/lesson-access.ts` требует счёт урока и **не меньше 75%** верных ответов
  в блоке (`GRAMMAR_PASS_RATIO`, порог считает `grammarPassMark`). Карточки
  можно просто пролистать, а наполовину понятое правило хуже непонятого:
  следующий урок всё равно на нём строится. Правило «пройденное не отнимаем»
  действует и здесь: блок, добавленный к давно пройденному уроку, не закрывает
  ни его, ни то, что ученик уже открыл, — слабая попытка тоже.
- **Счёт хранится отдельно** — `shifahiya-grammar-{id}`, не подмешивается к
  счёту урока. Иначе у всех, кто прошёл урок до появления блока, результат
  выглядел бы просевшим («26/28» превратилось бы в «26/56»).
- **Лексика — только пройденная.** `tests/grammar-block.test.mjs` проверяет это
  машинно: весь арабский в блоке урока N должен встречаться в колодах уроков
  1..N по согласному скелету (огласовки снимаются, приставочный `و` отделяется).
  Исключение — грамматические термины, они перечислены в тесте поимённо.
- **Термин учат как слово.** У правила рядом с арабским `term` идёт `termSound` —
  как термин звучит, кириллицей: `مُبْتَدَأٌ` → «мубтада», `نَصْبٌ` → «насб».
  Ученик, знающий только «подлежащее», не спросит про مبتدأ и не узнает его на
  слух. В ранних блоках термин вводится вместе с русским переводом, дальше по
  курсу — уже без него: «ставит мубтаду в насб». Транскрипция кириллицей,
  `ع` и `ء` внутри слова передаются через «ъ» (наът, маърифа, мафъуль бихи);
  тест требует `termSound` у каждого правила с `term`.
- **Уроки 97–100 закрывают курс разбором, а не правилами.** Их блоки не вводят
  нового: берут фразу самого урока и учат её разбирать — إِعْرَابٌ «иъраб».
  97 — именное предложение целиком, 98 — сравнение и частицы, переставляющие
  падеж, 99 — глагольное предложение в рассказе, 100 — два прохода: вазн даёт
  значение слова, иъраб — его роль. Поэтому лексика там сходится сама: весь
  арабский взят из колод того же урока.
- Экран правила — `view: "grammar"`, разметка `.rule-card` в `app/globals.css`.

### Тексты для чтения

Отдельный слой поверх курса: связные тексты по методу Франка из книги
«Мабдауль кыраат» — арабское предложение, по нажатию открывается русский
перевод. Это чтение, а не заучивание.

- **Лексика текстов в курс не входит.** Ни карточек, ни дистракторов, ни
  влияния на счёт и на открытие следующего урока. Условие, при котором чтение
  вообще добавляли: оно расширяет, что ученик может прочесть, а не то, что
  курс с него спрашивает.
- **Один текст на урок, уроки 35–96.** Хозяина выбирает не рука, а правило в
  `scripts/import-reading.mjs`: урок из этого промежутка, не разбитый на части
  и без грамматического блока (и то и другое уже даёт вторую часть), из таких —
  с наименьшим числом заданий. Сейчас это 25 уроков: 36, 40, 41, 42, 52, 65,
  66, 67, 69, 73, 75, 77, 78, 81, 82, 83, 84, 86, 87, 88, 90, 91, 92, 95, 96.
- **Своё расписание повторения** — `READING_INTERVALS = [2, 4, 7, 15, 31]` дней
  в `app/reading-review.ts`, ключ `shifahiya-reading-v1`. Коробки Лейтнера тут
  не подходят: текст не забывается за день и не вспоминается наполовину.
  Повторное чтение интервал только удлиняет, на последнем шаге держит.
- **Импорт данных**: `node scripts/import-reading.mjs <файл.json>` разбирает
  выгрузку переводчика в `content/reading/section-NN.ts` и пересобирает
  `content/reading-manifest.ts`. Скрипт понимает обе выгрузки: раннюю (пары с
  полем `lesson`, тексты размечены строками `type: "title"`) и сверенную с
  оригиналом (пары `id`/`section`/`ar`/`ru` без разметки текстов). Деление на
  50 текстов — книжное, поэтому оно хранится в скрипте таблицей `TEXT_STARTS`:
  id первой пары каждого текста. Повторный импорт его не теряет.
- **Название книги живёт в скрипте** (`SOURCE_TITLE`), а не берётся из выгрузки:
  сверенный экспорт называет её «Мабдауль усуль», книга же — «Мабдауль кыраат».
- **Текущая версия — сверенная с печатным оригиналом** (850 пар, 25 разделов).
  По сравнению с первой выгрузкой исправлено 582 перевода и 65 арабских
  фрагментов (71 замена внутри них). Одна особенность оставлена как в книге:
  в разделе 24 напечатано `إِذَا تَسْتَعْمِلِ الدَّوَاءَ ... لَا تُشْفَى أَبَدًا`, и перевод
  сохранён буквально — отрицания, которого нет в оригинале, не добавляли.
- Экран — `view: "reading"`, разметка `.reading-view` в `app/globals.css`.
  Чанк текста грузится при открытии, в стартовую разметку не попадает.

### Экзамены

Две контрольные точки: промежуточная после 50-го урока и итоговая после 100-го.
Карточка экзамена стоит в списке уроков там, где ему место, — сразу за уроком,
после которого он открывается.

- **Размер и состав.** Промежуточный — 100 вопросов, из них ровно 20 по
  грамматике. Итоговый — 150, грамматики не больше четверти (сейчас 36).
  Остальное — лексика: слова, устойчивые выражения и целые фразы; не меньше 70%
  лексических вопросов должны быть длиннее одного слова, это проверяет тест.
- **Проходной балл — три четверти и ещё один ответ**: `examPassMark` в
  `app/lesson-access.ts` даёт 76 из 100 и 114 из 150. Ровно три четверти — это
  черта, а черту нужно перейти.
- **Мелких вопросов нет.** Ни «как будет он», ни отдельного вопроса про
  окончание принадлежности — но и местоимения, и эти окончания встречаются
  внутри конструкций. Список запрещённых «вопросов в одно слово» лежит в
  `tests/exam.test.mjs` и проверяется машинно.
- **Лексика — только пройденная**, как и в грамматических блоках: весь арабский
  промежуточной работы должен встречаться в уроках 1–50, итоговой — в 1–100.
  Проверка сверяет согласный скелет, снимая огласовки, `و` и артикль.
- **Экзамен ничего не закрывает.** Он открывается, когда все уроки до него
  пройдены (включая грамматические блоки), и слабая попытка не отнимает ни
  открытого урока, ни прежнего результата: в `shifahiya-exams-v1` хранится
  лучший балл, число попыток и дата первой сдачи.
- **Работа сохраняется после каждого ответа** (`shifahiya-exam-session`): сто
  ответов слишком много, чтобы потерять их вместе с вкладкой. Порядок вопросов
  тасуется один раз при старте и хранится вместе с сессией.
- **Разбор — только в конце.** По ходу работы ответ не комментируется; на экране
  результата показываются первые 20 ошибок с верным ответом и объяснением.

## Вторая часть курса

Продолжение первой: упор на чтение, лексика идёт к текстам, а не тексты к
лексике. Источники — шесть книг подряд («Мабдауль кыраа» 2 и 3, «Кыраа рашида»
1 и 2, «Мин адабиль ислам», «Таглим мутагаллим»), около 105 уроков. Сейчас
загружены 14 уроков первой книги: 517 новых слов и 658 фраз в 44 рассказах.

- **Открывается по итоговому экзамену первой части.** Это и значит «набрал
  достаточно баллов»; пересдавать можно сколько угодно. Дальше уроки идут по
  порядку, и — как в первой части — пройденное не отнимается.
- **Урок в три шага.** Новые слова карточками (на обороте — фраза из текста,
  где слово встретится) → по одному заданию на слово → чтение всего текста.
  Урок засчитывается, когда прочитан текст: он здесь главный.
- **Задания строятся из данных, а не пишутся руками.** У каждой словарной
  единицы есть контекст; импортёр ищет в нём саму словоформу (снимая приставки,
  слитные местоимения и учитывая слабые корни) и кладёт её в `contextForm`.
  Нашлась — задание с пропуском на её месте; не нашлась — вопрос на смысл всей
  фразы. Сейчас 447 и 70. Дистракторы берутся из слов того же урока, сначала
  того же типа: глагол прячется среди глаголов.
- **Повторение общее с первой частью.** Карточки второй части лежат в той же
  коробке `shifahiya-card-progress-v1` под адресом `p2-lesson-{id}-word-{i}-{dir}`,
  поэтому в ежедневной очереди слова обеих частей идут вперемешку, и недоученное
  из первой продолжает выходить.
- **Тексты второй части не повторяются по расписанию** — в отличие от чтения
  первой части. Текст большой, читается один раз внутри своего урока.
- **Импорт данных**: `node scripts/import-part2.mjs <словарь.json> <текст.json>`.
  Первый файл — накопительный словарь новых слов по урокам (он уже вычтен
  относительно первой части), второй — тот же формат пар, что и у чтения первой
  части, с заголовками рассказов строками `type: "title"`. Строки без арабских
  букв (номера страниц, одинокие точки) отбрасываются, и скрипт печатает, что
  именно отбросил.

### Как добавить урок

1. Создать `content/lesson-NN.ts` (двузначный номер с ведущим нулём для 01–09),
   экспортировать `export const lessonNinetySix: Lesson = { ... }` — имя
   переменной прописью по-английски, `id` обязан совпадать с номером в имени файла.
2. Прогнать `npm run content:manifest` — урок сам подхватится глобом, ручной
   список импортов больше не нужен.
3. Добавить проверку в `tests/rendered-html.test.mjs` по образцу соседних уроков,
   там же поправить ожидаемое число файлов уроков.
4. Прогнать `npm test`.

**Арабский текст всегда с полной огласовкой (تشكيل)** — это учебный материал,
харакаты обязательны и в `decks`, и в `questions`.

**Ловушка с порядком огласовок.** Фатха + шадда и шадда + фатха выглядят
одинаково (`صَّ`), но это разные последовательности кодовых точек, и регулярка
в тесте не сработает. Нормальная форма (NFC) — сначала фатха (U+064E), затем
шадда (U+0651); файлы уроков в ней. Регулярку с арабской фразой не набирайте
руками — копируйте точную подстроку из файла урока.

Поле `description` пишется в формате `«N форм · 2 круга повторения · M заданий»`,
где `M = N * 2`. Число заданий относится к **итоговому** количеству после
автогенерации (см. ниже), а не к количеству авторских вопросов в файле —
расхождение с `questions.length` в исходнике нормально и ожидаемо. Число и
падежную форму («задание / задания / заданий») всё равно пересчитает
`expandLessonQuestions`, так что ошибиться в них не страшно — но в
`content/manifest.ts` попадает уже пересчитанное значение, поэтому после правки
урока манифест надо пересобрать.

### Как читать книгу (важно)

**Арабский текст из PDF не извлекается.** Шрифт с битой кодировкой: и `pypdf`,
и `pdftotext` выдают на арабском мусор с потерянными и переставленными буквами
(`الدَّرْسُ الأَوَّلُ` → `اليَّ لْ جُ الْل`). Полагаться на извлечённый арабский нельзя ни при
каких обстоятельствах — это прямой путь к ошибкам в учебном материале.

Рабочий способ — **читать страницы визуально**, инструментом `Read` с
параметром `pages` (до 20 страниц за раз). Требуется `poppler-utils`
(`apt-get install -y poppler-utils`), в свежем контейнере его нет. Огласовки
на рендере видны отчётливо.

Русская часть, наоборот, извлекается корректно:
`pdftotext -layout book.pdf book.txt` даёт русские подстрочные переводы с
сохранением колонок. Практичный режим работы — арабский с картинки, русские
глоссы из текстового слоя, сверяя друг с другом.

### Карта книги (номера страниц PDF)

| Раздел | Страницы |
|---|---|
| Титул, введение | 1–3 |
| **Часть I** (уроки 1–50) | 4–135 |
| **Часть II** (уроки 51–100) | 136–297 |
| Грамматика | 298–385 |
| Словарь | 386–426 |

Опорные точки: урок 1 — с. 5, урок 20 — с. 44, урок 30 — с. 75,
урок 35 — с. 91, урок 50 — с. 132, урок 51 — с. 137, урок 97 — с. 287.
Плотность неравномерная: в начале по 2 урока на страницу, дальше 3–6 страниц
на урок. Русские подзаголовки («Первый урок») есть только у первых ~35 уроков,
дальше заголовки только арабские (`الدَّرْسُ السَّابِعُ وَالتِّسْعُونَ`), так что искать урок
по номеру текстовым поиском бесполезно — нужно листать визуально от опорной точки.

### Структура урока в книге

Заголовок → тематические блоки новых слов с русским подстрочником →
«Переведите предложения на русский язык» (арабские фразы) →
«Переведите предложения на арабский язык» (русские фразы).

Отображение на нашу модель: блоки слов → `decks[]` (заголовок блока в
`deck.title`), фразы из обоих упражнений → `questions[]`. Последним вопросом
урока по нашей конвенции идёт задание «найдите и исправьте ошибку» — его в
книге нет, он составляется самостоятельно на материале урока.

## Ключевые механики (`app/page.tsx`)

- **`expandLessonQuestions`** (в `content/questions.ts`) добивает список вопросов
  до `words.length * 2` автосгенерированными парами (ар→ру и ру→ар) для каждого
  слова. Авторский последний вопрос («найдите ошибку») всегда остаётся последним.
- **Дистракторы** подбирает `buildOptions` там же. Кандидаты ранжируются по
  «спутываемости» (общий префикс/суффикс после снятия огласовок, близость длины)
  с бонусом за принадлежность к той же колоде; из лучшей половины (не более 6)
  два варианта выбираются детерминированным перемешиванием с сидом от ответа.
  Сид обязателен: генерация идёт на модульном уровне и должна совпадать на
  сервере и клиенте. Кандидат, у которого есть общее значение с ответом
  (`«высокий / длинный»` против `«длинный»`), отбрасывается — иначе у вопроса
  оказалось бы два правильных ответа.
- **Экраны** — одно состояние `view`: `home | learn | practice | review | result`.
  Роутинга нет, всё на одном URL.
- **Длинные уроки идут в две части.** Порог — `PART_THRESHOLD = 150` заданий в
  `content/lesson-parts.ts`; сейчас делятся 10 уроков (33, 44–49, 53, 54, 59).
  Карточки режутся по границе колоды, ближайшей к середине (колода — одна тема,
  разрывать её нельзя), задания — ровно пополам, поэтому завершающее «найдите
  ошибку» остаётся во второй части. Счёт и список ошибок копятся через обе
  части, поэтому итог — за весь урок. Когда первая часть закончена, сессия
  сразу сохраняется на начало второй: уйти с экрана результата можно, не
  потеряв пройденное. `finishLesson` вызывается только на последней части — до
  этого урок не считается пройденным.
- **Загрузка контента ленивая.** Главная рендерится из `content/manifest.ts`
  (сгенерированные метаданные, ~39 КБ), сам урок приезжает отдельным чанком
  при открытии — `openLessonsById` в `app/page.tsx`. На старте подгружаются
  только урок незавершённой сессии и уроки, по которым есть карточки
  повторения. `reviewCatalog` строится из загруженных уроков, а не из всего
  курса. Поэтому `lesson` может быть `undefined` — режимы `learn`/`practice`/
  `result` закрыты проверкой, пока урок не приехал.
- **Интервальное повторение**: `REVIEW_INTERVALS = [0, 1, 3, 7, 14, 30]` дней,
  коробки Лейтнера. Каждое слово даёт две карточки (`ar-ru` и `ru-ar`), id вида
  `lesson-{id}-deck-{i}-word-{j}-{direction}`. Слово считается выученным, когда
  **обе** карточки в максимальной коробке.
- **Хранилище — `localStorage`**, читается через `useSyncExternalStore`
  в `app/progress-store.ts`: сервер отдаёт пустой снимок, гидрация с ним
  совпадает, сохранённые значения приезжают тем же механизмом, что React
  использует для любого внешнего источника. Копировать localStorage в
  `useState` на маунте не нужно и нельзя — правило `set-state-in-effect`
  на это ругается. Ключи:
  `shifahiya-lesson-{id}` (счёт), `shifahiya-grammar-{id}` (счёт грамматики),
  `shifahiya-session-{id}` и
  `shifahiya-active-session` (незавершённая сессия), `shifahiya-card-progress-v1`,
  `shifahiya-reading-v1` (расписание чтения), `shifahiya-exams-v1` (результаты
  экзаменов), `shifahiya-exam-session` (незаконченная работа),
  `shifahiya-p2-lesson-{id}` и `shifahiya-p2-session-{id}` (вторая часть),
  `shifahiya-learning-stats-v1`. Плюс ручной экспорт/импорт JSON
  (`format: "shifahiya-progress", version: 1`) — при изменении формата поднимать
  `version` и суффикс `-vN` в ключах.
- **Синхронизация между устройствами — Supabase, необязательная.**
  `app/supabase-config.ts` пустой по умолчанию; пока он пустой, `startSync()`
  выходит сразу, панель входа не рендерится и наружу не уходит ничего.
  Заполнены — на главной появляется кнопка входа через Google. Провайдер, а не
  ссылка на почту: встроенная почта Supabase ограничена парой писем в час.
  - `localStorage` остаётся источником истины, сервер — копия. Офлайн-режим
    ломать нельзя: это условие, при котором синхронизацию вообще добавляли.
  - Вход **не перезаписывает** местный прогресс. `app/merge-progress.ts` —
    чистый модуль слияния: счёт — максимум, карточка — та, где позже
    `lastReviewed` (дальше по `box`, затем по числу ответов), сессия — свежая
    по `updatedAt`, даты и фразы — объединение. Слияние коммутативно, это
    проверяется тестом; `masteredPhrases` и `activeDates` для этого сортируются.
  - Импортирует из `progress-store` **только типы** (`import type`) — иначе
    тест не сможет загрузить модуль под `--experimental-strip-types`.
  - `app/sync.ts` держит состояние входа во втором внешнем сторе
    (`syncStore`) и грузит `@supabase/supabase-js` динамическим импортом:
    пакет весит вдвое больше всего курса и в стартовый чанк попадать не должен.
    Проверять после правок: чанка `dist-*.js` не должно быть в разметке
    `.static-site/index.html`.
  - Пуш дебаунсится (`SETTLE_MS`) с потолком ожидания (`MAX_WAIT_MS`) и
    досылается на `pagehide`/`visibilitychange`: полный прогресс — около
    мегабайта JSON, отправлять его на каждый ответ нельзя.
  - Схема БД и политики RLS — `supabase/schema.sql`, применяется вручную через
    SQL Editor. Ключ `anon` публичный по замыслу, доступ ограничивают политики.
- **Озвучка** — Web Speech API, `speak()` с `lang = "ar-SA"`. Поле `Word.audio`
  объявлено, но не заполнено и нигде не читается — задел на реальные аудиофайлы.

## Тесты

`npm test` собирает проект и прогоняет `tests/*.test.mjs` под
`--experimental-strip-types` — благодаря этому тесты импортируют `.ts`-модули
напрямую (с обязательным расширением в пути). `content/lessons.ts` так
импортировать нельзя: `import.meta.glob` разрешает только сборщик, — поэтому
в тестах уроки грузятся чтением каталога.

`tests/questions.test.mjs` — настоящие поведенческие проверки генератора на всех
100 уроках: добивка до `words * 2`, уникальность вариантов, отсутствие второго
правильного ответа, разнообразие дистракторов и детерминированность. Новую
логику генерации проверять здесь.

`tests/rendered-html.test.mjs` делает две вещи: (1) импортирует собранный
`dist/server/index.js` и проверяет SSR-разметку главной, (2) читает исходники
как **текст** и проверяет их регулярками.

Второй тест хрупкий и растёт линейно с числом уроков (~100 `readFile` подряд).
При правках `app/page.tsx` он может упасть на регулярке, а не на реальной
поломке — это ожидаемо, регулярку в таком случае надо обновлять вместе с кодом.
Тест **не должен** мешать рефакторингу: если проверка привязана к формулировке
кода, а не к поведению, её правильно переписать на структурную или перенести
в `questions.test.mjs`.

## Известные проблемы (актуальный техдолг)

Крупного долга не осталось. Мелочи:

1. `worker/index.ts` ссылается на тип `Fetcher` из Cloudflare Workers, которого
   нет в `tsconfig` — единственная ошибка `npx tsc --noEmit`. На сборку не
   влияет, типы стираются.
2. Второй тест в `tests/rendered-html.test.mjs` проверяет исходники
   регулярками и растёт линейно с числом уроков.

## Принятые решения

- **Синхронизация — Supabase, а не D1.** Требование появилось («чтобы прогресс
  не терялся на разных устройствах»), и выбран Supabase: сайт остаётся
  статикой на GitHub Pages, а готовая авторизация избавляет от своей. Скаффолдинг D1 (`db/`, `drizzle/`, `drizzle.config.ts`,
  `examples/d1/`, пакеты `drizzle-orm` и `drizzle-kit`) был удалён раньше как
  мёртвый груз и не возвращается. SIWC-хелперы (`app/chatgpt-auth.ts`)
  оставлены, но задачу не решают: они серверные и требуют хостинга OpenAI Sites.
  Ключевое условие, при котором синхронизацию согласовали, — она идёт **поверх**
  локального состояния, а не вместо него.
- **Рефакторинг `app/page.tsx` и тестов разрешён** без отдельного согласования.
- Дописывать уроки 96–100 сейчас не требуется; книга-источник уже в репозитории
  (см. раздел «Источник контента»).
