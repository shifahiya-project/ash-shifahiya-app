# Как написать тему для части «Темы наизусть»

Этот документ — полная инструкция по одной задаче: **превратить раздел книги в
тему приложения.** Его можно целиком скопировать в любую другую модель и
получить на выходе готовый файл. Ничего, кроме этого документа и самого текста
раздела, для работы не нужно.

Готовый результат — **один файл** `content/topics/<slug>.ts` плюс одна строка в
`content/topics/catalog.ts`. Больше ничего: ни экранов, ни скриптов, ни правок
в коде. Часть «Темы наизусть» уже умеет всё остальное.

---

## 1. Главное условие: текста книги в приложении нет

Ученик читает раздел **по своей книге**. Приложение даёт то, чего чтение не
даёт:

- вопросы, которые заставляют вспомнить, а не узнать;
- разборы и расчёты по таблицам раздела;
- расписание, по которому всё это возвращается, пока не останется в памяти.

Отсюда два следствия, нарушать которые нельзя:

1. **Не пересказывать текст.** Тема — это вопросы и ответы, а не конспект.
2. **У каждой единицы стоит страница книги** (`page`). Ответ на экране должен
   проверяться по оригиналу в одно движение. Страница обязана попадать в
   диапазон, объявленный у темы (`source.pages`), — это проверяет тест.

И главное правило честности: **что книга не сказала, того не говорим.** Если
фраза в книге обрывается или правило названо без последствия — так и пишем в
`note` («книга не указывает; сверьтесь с учителем»). Додумать за автора — то же,
что переврать его.

## 2. Как устроена тема

```
Тема (Topic)
├── source      — книга, раздел, страницы, выходные данные
├── steps[]     — занятия, обычно по подразделам книги
│   ├── brief[] — 3–4 опорных тезиса занятия (наши, не книги)
│   ├── atoms[] — вопросы: факты и списки
│   └── drills[]— тренажёры: разборы, порядки, расчёты (необязательно)
└── exam        — вопросы самой книги для самопроверки
```

Ученик проходит занятие (карточки вопросов), потом они возвращаются к нему по
расписанию `[0, 1, 3, 7, 16, 35, 90]` дней. Форма вопроса зависит от того,
насколько он знаком: новый или только что забытый факт с написанными вариантами
предлагается выбором, дальше — только свободным припоминанием с самооценкой в
три кнопки. Список всегда спрашивается списком: ученик вспоминает вслух,
открывает и отмечает то, что действительно назвал.

**Тема может быть написана на прочитанную часть книги.** Следующая глава
дописывается в конец `steps` и в конец зачёта и ничего не сдвигает: карточка
адресуется парой `тема:id-вопроса`, а не местом в списке.

## 3. Формат файла (точные типы)

Файл начинается ровно так:

```ts
import type { Topic } from "./types.ts";

export const zakatTopic: Topic = { ... };
```

Имя переменной — `<slug>Topic`, латиницей. Всё содержимое — по-русски.

```ts
type Topic = {
  id: string;            // латиницей, без пробелов: "zakat", "hajj", "mirath"
  title: string;         // «Закят», «Паломничество»
  subtitle: string;      // одна строка под заголовком в списке тем
  source: {
    book: string;        // название книги — оно видно на карточке темы
    section: string;     // «Раздел 4. Закят», «Глава I. Основные понятия»
    pages: string;       // «98–110» — через тире-минус U+2013
    note?: string;       // издание, автор, оговорки; показывается на экране темы
  };
  intro: string;         // 2–3 предложения: что за тема и из чего состоит
  steps: TopicStep[];
  exam: {
    title: string;       // «Зачёт по разделу» / «Зачёт по главе»
    intro: string;
    questions: TopicExamQuestion[];
  };
};

type TopicStep = {
  id: string;            // латиницей, уникально внутри темы: "usloviya"
  title: string;         // «Условия обязательности и нисаб»
  pages: string;         // страницы книги именно этого занятия: «99–100»
  brief: string[];       // 3–4 тезиса: что держать в голове, читая эти страницы
  atoms: Atom[];
  drills?: Drill[];
};

type Atom = {
  id: string;            // латиницей, уникально внутри темы
  kind: "fact" | "list";
  question: string;      // вопрос ученику
  answer: string;        // для факта — ответ; для списка — рамка: «Их шесть.»
  items?: string[];      // только у списка: пункты перечисления
  note?: string;         // уточнение, которое показывается после ответа
  evidence?: { text: string; source: string };  // аят или хадис книги
  options?: string[];    // 2–3 неверных варианта (только у факта)
  page: number;          // страница книги
};

type TopicExamQuestion = {
  id: string;            // «1», «2», … сквозной нумерацией
  prompt: string;        // вопрос книги дословно
  atoms: string[];       // id атомов, из которых собирается эталон ответа
  extra?: string;        // то, чего нет ни в одном атоме: разбор задачи, ответы а)б)в)
};
```

## 4. Как разбирать текст: правила

1. **Занятия — по подразделам книги.** 5–12 фактов на занятие. Если подраздел
   огромен (как «Нарушения и искупления» в хадже) — можно разбить надвое, если
   крошечный — слить с соседним.
2. **Каждое утверждение книги — вопрос с коротким ответом.** Вопрос должен быть
   таким, чтобы на него отвечали вслух одной-двумя фразами.
3. **Перечисления не разрывать.** Всё, что книга сама перечисляет («условий
   шесть», «восемь групп»), — это `list` целиком, а не шесть отдельных фактов.
   В `answer` идёт рамка: «Их шесть.», «Книга называет девять.»
4. **Неверные варианты пишутся руками и только там, где спутать есть что.**
   Хорошие варианты — это соседнее правило той же книги: 85 г против 595 г, одна
   десятая против одной двадцатой, фард против ваджиба. Плохие — выдуманная
   бессмыслица: отвергать её ученик научится мгновенно и ничему не научится.
   Нет очевидной путаницы — не пишите `options` вовсе, вопрос будет спрашиваться
   свободным припоминанием. В среднем варианты есть у трети фактов.
   **Ни один вариант не должен быть верным ответом другими словами.**
5. **`note` — для уточнения, которое не тянет на отдельный вопрос**: исключение,
   мнение другого мазхаба, единица измерения, оговорка книги.
6. **`evidence` — для аята или хадиса, который книга приводит как довод.**
   `text` — сама цитата, `source` — кто передал и где приводится, как в книге.
7. **`brief` — наши тезисы, а не пересказ.** Их читают перед занятием: что
   держать в голове, читая эти страницы, и на что там обычно попадаются.
8. **Страница обязательна у каждого атома и каждого тренажёра**, и это должна
   быть та страница, где утверждение напечатано.

## 5. Тренажёры: шесть видов

Тренажёр — такая же карточка расписания, как факт, но задание генерируется
заново при каждом показе: число, набор или окно каждый раз другие. Поэтому
запомнить ответ нельзя — можно только уметь.

### `sort` — разбор на кучки (2, 3 или 4)

Самый частый и самый полезный. Берётся там, где книга делит вещи на разряды.

```ts
{
  id: "drill-kaffara",
  kind: "sort",
  title: "Разбор: какое искупление",
  prompt: "Какое искупление предусмотрено за каждое из этих нарушений?",
  buckets: ["Жертвоприношение", "Садака фитр", "Горсть пшеницы"],
  size: 6,                       // сколько пунктов в одном задании
  items: [
    { label: "Шитая одежда в течение дня или ночи", bucket: 0 },
    { label: "Шитая одежда меньше дня, но больше часа", bucket: 1 },
    { label: "Шитая одежда меньше часа", bucket: 2 },
    { label: "Накрыться одеждой, не надевая её", bucket: 1, note: "Нарушение — надеть, а не накрыться." },
  ],
  page: 126,
}
```

`bucket` — индекс в `buckets`. В каждой кучке должен быть хотя бы один пункт;
`size` — не больше числа пунктов и желательно не меньше числа кучек, иначе
кучка выпадет из задания. Примеры: «фард / ваджиб / сунна», «наследует / не
наследует», «можно давать закят / нельзя», «ханафиты / маликиты / шафииты /
ханбалиты».

### `order` — порядок действий

Берётся там, где книга описывает последовательность: обряд, очерёдность выплат,
этапы. В `items` — весь порядок, задание берёт из него окно в `size` подряд
идущих шагов и перемешивает.

```ts
{
  id: "drill-order-actions",
  kind: "order",
  title: "Порядок: что из наследства платится раньше",
  prompt: "Расставьте действия с имуществом усопшего по порядку — от первого к последнему.",
  size: 4,                        // не больше длины items
  items: ["Расходы на похороны", "Долги", "Завещание — не больше трети", "Наследование"],
  page: 17,
}
```

### `estate` — раздел наследства

Для главы, которая учит делить сумму между наследниками. Задание называет
сумму, набор наследников и спрашивает про одного из них; чтобы ответить, надо
пройти весь расчёт, а проверяется одно число — точно.

```ts
{
  id: "c3-drill-estate",
  kind: "estate",
  title: "Расчёт: раздел наследства",
  currency: "₽",
  values: [5000, 10000, 15000, 20000, 25000],   // чем задаётся размер наследства
  cases: [
    {
      heirs: [
        { label: "жена", count: 1, fard: [1, 8], spouse: true },
        { label: "отец", count: 1, fard: [1, 6] },
        // вес 2 у мужчины, 1 у женщины; each — как назвать одного из группы
        { label: "два сына", count: 2, each: "каждый из двух сыновей", residue: 2 },
        { label: "дочь сына", count: 1, blocked: "не допущена сыновьями" },
      ],
      note: "Чем этот случай важен — говорится после ответа.",
    },
  ],
  page: 101,
}
```

Три вещи, которые генератор делает сам и вписывать их не надо:

- **основу долей** — общий знаменатель обязательных долей;
- **поправку** — долей больше основы, значит ‘ауль; меньше, и наследника
  остатка нет, значит радд, причём супруг в приращении не участвует;
- **сумму задания** — генератор берёт число из `values` и умножает его на
  наименьший множитель, при котором каждая выплата выходит целыми деньгами.

**`values` — это не стоимость доли.** Стоимость доли считается из основы, а
поправка её меняет, поэтому предсказать её по `values` нельзя и не нужно:
`values` задаёт только порядок суммы. Для случая «жена, два сына, дочь» число
5000 даёт наследство 200 000 ₽ и стоимость доли 25 000 ₽.

**У строки, где людей несколько, обязательно пишите `each`** — как назвать
одного из них: «каждая из трёх жён». Ответ у такой строки всегда доля одного
человека, и вопрос обязан спрашивать именно её; по-русски это склонение, и
собрать его из `count` и `label` нельзя.

Пишите в данных только то, что говорит книга: кто пришёл, какая у него
обязательная доля, кто берёт остаток и кто не допущен. Какая поправка нужна —
следствие, а не пометка.

### `steps` — ступенчатая таблица

Для таблиц вида «столько-то голов — столько-то причитается».

```ts
{
  id: "drill-sheep",
  kind: "steps",
  title: "Расчёт: закят с овец",
  prompt: "Сколько закята выплачивается с {n}?",   // {n} подставится числом
  noun: ["овцы", "овец", "овец"],                  // 1 овцы, 2 овец, 5 овец
  below: "Закята нет: нисаб не достигнут.",        // ниже первого порога
  steps: [
    { from: 40, due: "Одна овца." },
    { from: 121, due: "Две овцы." },
    { from: 201, due: "Три овцы." },
  ],
  cycle: { from: 400, every: 100, noun: ["овца", "овцы", "овец"] },  // «после 400 — по одной с сотни»
  range: [1, 700],                                  // какие числа предлагать
  page: 103,
}
```

### `share` — доля от величины

Для «одна десятая при естественном орошении, одна двадцатая при искусственном».

```ts
{
  id: "drill-harvest",
  kind: "share",
  title: "Расчёт: закят с урожая",
  prompt: "С поля собрали {base}. Орошение {variant}. Сколько выплачивается закята?",
  unit: ["центнер", "центнера", "центнеров"],
  variants: [
    { label: "естественное — дождями и реками", per: 10 },
    { label: "искусственное — водой из сосудов", per: 20 },
  ],
  range: [40, 800],
  step: 20,        // числа кратны step, чтобы деление всегда было целым
  page: 104,
}
```

### `money` — порог и процент

Для «есть ли обязанность вообще, и сколько, если есть».

```ts
{
  id: "drill-money",
  kind: "money",
  title: "Расчёт: деньги и нисаб",
  currency: "₽",
  prices: [5000, 6000, 7500, 8000],   // цена грамма золота, называется в задании
  nisabGrams: 85,
  rate: 0.025,
  range: [200000, 2000000],
  step: 40000,
  debts: [0, 0, 0, 120000, 300000],   // ноль тоже вариант
  page: 100,
}
```

**Если в разделе нет ни таблиц, ни порядков, ни разрядов — тренажёров может не
быть вовсе.** Выдумывать их не надо.

## 6. Зачёт

- **Берутся вопросы самой книги** — «Вопросы для повторения», «Вопросы и задания
  для самопроверки». Дословно, как напечатаны, даже если формулировка неточна.
- Если книга спрашивает **после каждого подраздела**, а не одним списком в конце,
  — собрать их в порядке чтения. Нумерация всегда сквозная: `"1"`, `"2"`, … без
  пропусков.
- **Эталон ответа не пишется заново.** В `atoms` перечисляются id атомов, из
  которых он собирается на экране. Две копии одного правила разойдутся на первой
  же правке.
- **`extra`** — только для того, чего нет ни в одном атоме: ответы на конкретную
  задачу («а) 26 верблюдов — одна годовалая верблюдица»), разбор числового
  примера, оговорка о формулировке вопроса.
- Своих вопросов не добавляем. Если книга вопросов не даёт — зачёта у темы нет,
  и это нормально: `questions: []`.

## 7. Чек-лист перед сдачей

Проверить глазами — в репозитории это же проверяет автоматический тест:

- [ ] Все `id` (атомов и тренажёров) **уникальны внутри темы**, латиницей.
- [ ] У каждого атома и тренажёра есть `page`, и он **внутри** `source.pages`.
- [ ] У `kind: "list"` есть `items` (минимум два), у `kind: "fact"` их нет.
- [ ] `options` — только у фактов, 2–3 штуки, без повторов, **ответа среди них
      нет**, и ни один из них не является верным ответом другими словами.
- [ ] Вопросы зачёта пронумерованы подряд от `"1"`, и каждый ссылается только на
      существующие id атомов.
- [ ] У `sort`: каждая кучка непуста, `bucket` меньше числа кучек, `size` не
      больше числа пунктов.
- [ ] У `order`: `size` не больше длины `items`, шаги не повторяются.
- [ ] У `steps`: пороги идут по возрастанию.
- [ ] У `share` и `money`: `range` и `step` подобраны так, что деление даёт целое.
- [ ] Нигде не выдумано правило, которого нет в книге.

## 9. Что делать с готовым файлом

1. Положить его в `content/topics/<slug>.ts`.
2. В `content/topics/catalog.ts` добавить импорт и одну строку в массив:

   ```ts
   import { namazTopic } from "./namaz.ts";
   export const TOPICS: Topic[] = [zakatTopic, hajjTopic, mirathTopic, namazTopic];
   ```

3. Прогнать `npm test` — тест тем проверит весь чек-лист из раздела 7.
4. `npm run build:static && npm run smoke` — прогон в браузере.

Сводку (число занятий, фактов, тренажёров) вписывать никуда не надо: она
считается по самой теме.

### Если это новая глава к уже существующей теме

Тема растёт главами, и это ничего не сдвигает — но ровно при одном условии:
**всё, что уже было, должно остаться тем же.** Адрес карточки в расписании
ученика — `тема:единица`, то есть id атома или тренажёра. Переименованный id
это потерянная карточка; изменённый текст вопроса — это другой вопрос под
старым расписанием.

Поэтому новая глава **дописывается**, а не переписывается:

- новые занятия идут в **конец** `steps`, новые вопросы — в **конец** зачёта, с
  продолжением сквозной нумерации;
- id старых атомов, тренажёров и вопросов **не трогаются вообще** — ни ради
  единообразия, ни ради порядка;
- меняются только `subtitle`, `source.section`, `source.pages`, `intro` и
  `source.note`: они описывают тему целиком, а карточек не адресуют;
- новым id полезно дать приставку главы (`c2-…`), чтобы они заведомо не
  столкнулись со старыми.

Перед тем как положить файл на место, **сверьте старое со старым** — это одна
команда, и она отвечает на единственный вопрос, который тут важен:

```bash
# подставьте свою тему вместо mirath
cp <новый файл> content/topics/_new.ts
node --experimental-strip-types --input-type=module -e '
import { mirathTopic as o } from "./content/topics/mirath.ts";
import { mirathTopic as n } from "./content/topics/_new.ts";
const m = (t) => Object.fromEntries(
  t.steps.flatMap((s) => [...s.atoms, ...(s.drills ?? [])].map((u) => [u.id, JSON.stringify(u)])));
const a = m(o), b = m(n);
console.log("пропало:", Object.keys(a).filter((k) => !(k in b)));
console.log("изменилось:", Object.keys(a).filter((k) => k in b && a[k] !== b[k]));
console.log("вопросы зачёта сдвинулись:",
  o.exam.questions.filter((q, i) => n.exam.questions[i]?.id !== q.id).length);
'
```

Три пустых ответа — можно ставить; иначе чья-то карточка меняет смысл, и это
надо чинить до, а не после.

**Дописывая последнюю главу, не дублируйте то, что уже спрошено.** Книга часто
кончается словарём или сводной таблицей, повторяющей разобранное. Берите оттуда
только то, чего тема ещё не спрашивала: вторая карточка на то же правило — это
два ответа, которые разойдутся при первой же правке одного из них.

Скопируйте весь этот документ, а следом — такое задание:

> Ты пишешь тему для приложения по инструкции выше. Материал — текст раздела,
> который я пришлю следующим сообщением (или страницами книги).
>
> Сделай:
> 1. Разбей раздел на занятия по его подзаголовкам, 5–12 фактов на занятие.
> 2. Каждое утверждение книги преврати в вопрос с коротким ответом; перечисления
>    оформи списками целиком.
> 3. Там, где спутать есть что, допиши 2–3 неверных варианта — не выдумки, а
>    соседние правила той же книги.
> 4. Таблицы, порядки действий и деления на разряды вынеси в тренажёры.

>

Устройство, которое уже готово и новой теме достаётся даром:

- **расписание** `[0, 1, 3, 7, 16, 35, 90]` дней, три оценки («не вспомнил» —
  в начало и считается потерей, «с трудом» — держит интервал, «вспомнил» —
  двигает дальше); не вспомненный вопрос переспрашивается в той же сессии;
- **формы вопроса**: выбор для новых и только что забытых фактов, свободное
  припоминание дальше, список с отметками по пунктам, шесть видов тренажёров;
- **зачёт** по вопросам книги: «ответил» ничего не меняет, «частично» опускает
  факты вопроса на коробку ниже, «не ответил» возвращает их в начало;
  проходной балл — три четверти и ещё один ответ;
- **синхронизация** между устройствами вместе с прогрессом курса;
- **счётчик на главной**: сколько вопросов тем ждёт сегодня.

Тесты (`tests/topics.test.mjs`) проверяют весь чек-лист из раздела 7 по всем
темам сразу, а прогон в браузере (`npm run smoke`) проходит занятие темы
целиком и проверяет, что оценка доходит до расписания.

## 12. Частые ошибки

- **Пересказ вместо вопроса.** «В этом разделе говорится о…» — это не атом.
- **Список, разорванный на факты.** Перечисление проверяется целиком, иначе
  ученик выучит три пункта из восьми и будет считать, что знает.
- **Вариант-синоним.** Если неверный вариант — это верный ответ другими
  словами, у вопроса два правильных ответа.
- **Выдуманные варианты-пустышки.** Отвергать бессмыслицу — не упражнение.
- **Страница «примерно».** Страница нужна затем, чтобы сверяться с книгой.
- **Додуманное правило.** Книга умолчала — умолчите и вы, с пометкой в `note`.
- **Свои вопросы в зачёте.** Зачёт — это вопросы книги, и только они.
